# ingest

Process one raw source into a source page, then create or update the concept/entity pages it supports. One skill, three composable modes — **new vs. existing** (auto-detected by whether `1-wiki/sources/{stem}.md` exists), **normal vs. deep** (source-page depth), and optional **frames** (angles scoping the page) — composing on one shared spine (read → write/update the source page → create/update concept-entity pages → verify). What each mode adds:

| Mode | What it adds to the spine |
|---|---|
| New (default) | Create the source page first-time; propose new concept/entity pages; add index entries. |
| Existing (page exists) | Confirm a reason; run the always-on checks (`references/existing-mode.md`); attachment keep/replace/remove/add; cascade `needs-update` to dependents; preserve `created:`. |
| Normal depth (default) | High-level orientation only. |
| Deep (explicit opt-in) | Reference-grade source page (equations, hyperparameters, tables, more figures, deeper Method/Appraisal) within a stated purpose. Concept/entity pages stay atomic. |
| Frames (optional) | Scope every source-page section to the frames' union (an upper bound on scope — sections no frame admits stay empty); save each to `frames:`. |

## Purpose

The source page preserves what this source contributes and where the exact evidence lives. Concept/entity pages capture reusable ideas in simple language — do not turn them into source summaries.

**New vs. existing source (auto-detect)** — detected in Step 1 by whether `1-wiki/sources/{stem}.md` exists. New creates the source page first-time and proposes the concept/entity pages it genuinely supports. Existing reingests in place for a stated reason, updating the evidence layer without bloating concept/entity pages into source summaries — but "bloat" is source-summary detail, not source support, so attaching a genuinely-supporting source and the claims it contributes (including to a page the re-read newly reveals it supports) is maintaining the cross-source record, not bloat. It prevents duplicate source pages and preserves the prior view via git history (Step 5 clean-tree precondition). Terminology: "update" = any in-place modification; "refresh" = a reingest (of any reason), of which `schema refresh` is one named reason.

**Depth.** Default normal; deep is an explicit opt-in Step 1 asks about, never inferred from the source or the request's tone. Deep — the longest-lasting page in the wiki and the easiest to bloat — **requires a stated depth purpose**: what the depth is *for* (a frame, a paper section the page will support, a specific question, a paper being written). "I want a thorough page" is not a purpose; it produces an indiscriminate source dump. Deep expands the *depth* of in-scope sections, never the breadth of out-of-scope ones, and never the concept/entity pages (which stay one-idea and simple regardless). Throughout, `ingest-deep` is the verb token used in log and hot entries.

**Frames are the ceiling, not a starting point.** A frame (lens, angle) is one positive scope on the source page — "only the attention-efficiency results", "the optimizer-convergence proof" — and `frames:` may hold several, the page scoped to their union. Every section is scoped to that union; sections no frame admits stay at the empty placeholder (`> - None noted`), never filled from outside the frames even when the source supports it. The raw is still fully read (Step 2; for a book, its chosen chapter/page range), and Step 8 judges the page against the frames' union (or deep purpose), not the whole source — a thin page under a narrow frame is the correct outcome. In deep mode a frame, when given, *is* the depth purpose. A frame is a positive lens, never a hard exclusion, so reframing only ever *adds*; the reuse / append / clear decision and its scope-widening test are in `references/existing-mode.md`.

**A frame may be a pre-applied analysis layer.** When the frame is a categorization the user already attached to the source (tags, a typology, a labelling scheme), treat those labels as the user's analysis layer, not facts about the source: assess each against what the source actually does — never copy them verbatim as characterizations, never blanket-reject them. The page stays grounded in the source's own language, not the frame's vocabulary. (Project-specific frame conventions live in `ingest-memory.md`.)

**Sections are not quotas.** Required callout sections must appear in every page, but they do not all need content. If a section has nothing genuine and source-supported to say, leave the empty placeholder (`> - None noted` for source pages, `> - None yet` for concept/entity pages). A page with several placeholders is correct when the source genuinely earns nothing there. Do not invent, paraphrase, or pad to avoid an empty section. Deep ingest expands the depth of filled sections, not their count.

**Pattern: analyze → plan → validate → execute → verify.** Step 2 analyzes (reads the source); Step 3 plans and validates (per-decision `AskUserQuestion`, user approval the gate); Steps 4–7 execute only approved edits; Step 8 verifies and sets status.

**Ingest owns its claims.** Step 8 is narrow and mechanical by design: it takes exactly the claims this run wrote and asks three questions of each against the raw still open — is the page number right, does the source really say this, is the claim attached to the source that states it — through independent refuters. Doing it here is nearly free (the raw is open, the provenance known) and expensive anywhere else, so ingest does not hand its claims on to be re-checked: when they hold and the page is otherwise sound, ingest sets it `verified` itself. What ingest does *not* own is the whole-page judgement — one idea or three, duplicates an existing page, contradicts the wiki, connectedness, LLM voice. Those need the finished page in view and belong to `audit`; Step 8's page self-check is a first pass at that prose, not a substitute for it, and never blocks the run.

**Verification stands in for human re-voicing.** The smart-note method has a human re-voice the note at a commit point; this wiki keeps pages LLM-drafted, so Step 8's checks plus a later `audit` are load-bearing, not optional.

## Conventions (recap)

- **Source-page filename matches the raw source stem exactly** (drop the extension, preserve case and internal punctuation): `0-raw/papers/<bibkey>.pdf` → `1-wiki/sources/<bibkey>.md`; `0-raw/articles/<slug>.md` → `1-wiki/sources/<slug>.md`. The attachments folder uses the same stem: `1-wiki/attachments/{stem}/`.
- **Every wikilink is path-qualified from the repo root, includes `.md`, and uses a pipe-rendered display name** that reads naturally: `[[1-wiki/concepts/scaled-dot-product-attention.md|Scaled Dot-Product Attention]]`, authors `[[1-wiki/entities/ashish-vaswani.md|Ashish Vaswani]]`. The pipe display is required (a bare path renders unreadably) and carries no whitespace around the pipe (`[[path|display]]`, never `[[path | display]]`); attachment embeds `![[...]]` take the path but no pipe.
- **No bold and no italic in wiki content** (source, concept/entity, synthesis, hot/index/log). The only structural exceptions are LaTeX math and the bullet markers `*\[unverified\]*` / `*\[tentative\]*` / `*\[disputed — see Contradictions\]*`. Inline backticks for paths, code, and quoted prompt addenda are fine.
- **Use `AskUserQuestion` for every user-facing decision** in Step 3. One decision per question; do not batch. Mark the option you recommend `(Recommended)` and place it first — base the lean on your read of the source (e.g. `Include (Recommended)` for a clearly-warranted concept page, `Drop (Recommended)` for a marginal candidate). Omit a recommendation only on a genuine no-lean call, and say so in the question. Phrase every question and option label for a reader who knows nothing about the wiki's internal vocabulary — gloss any callout, status, or frames term inside the option (present `add to Not This` as "record as a contrast (Not This)", `mark needs-update` as "flag for re-checking (needs-update)", `clear to unscoped` as "widen back to the whole source"), the same way the Step 1 depth question already describes both modes plainly.
- **Structural authority lives in `CLAUDE.md`.** Required-section lists, frontmatter blocks, block-ID placement, and locator rules are the shared schema — this skill cites `CLAUDE.md` rather than copying (copying drifts). The Step 8 verification spec lives in the shared `.claude/skills/multi-skill/references/verification.md` (one canonical copy, since `query`, `synthesis`, and `supersede` run the same checks). The extraction/citation *procedures* the agent runs are self-contained in the skill's steps and `references/`.
- **Status and markers (recap).** Ingest sets each touched page's status in Step 8, on what its claim check established — `verified` when the four Setting Status conditions hold (`.claude/skills/multi-skill/references/verification.md`), `draft` when a claim is neither certified nor honestly marked, `needs-update` on an unresolved problem. **Certification reaches only as far as the raw read this run:** a claim cited to a *different* source is not ingest's to certify — leave it if it was already certified on an entering-`verified` page, else mark it `*[unverified]*` as the pending delta (a masked line never enters `verified_hash`). Never mark a claim cited to *this* run's raw instead of checking it. On a `verified` page a reingest edits, a **changed** claim the run re-certifies keeps the page `verified` and re-stamps; one it does not re-certify moves the hash and demotes to `draft` (marking does not hold it), as do an uncertified embed or `Sources` change and a `frames:` scope-widening. Mechanical frontmatter touches (`updated:`, `source_count:`) are hash-safe. Full rules: `CLAUDE.md` → Page status and Bullet markers.

## When to invoke

Use when the user names a specific raw file under `0-raw/` and asks to ingest, process, capture, digest, import, deep-ingest, reingest, or refresh it. Implicit phrasings count too — "add this paper to the wiki", "make a source page for X", "write up this PDF", "summarize this PDF into the wiki", "take notes on this paper". (Absent any destination signal, "take notes on this paper" defaults to ingest — the wiki. Route elsewhere only when the user names an external structured database as the destination and the project actually defines a capture skill for it; see When Not To Invoke.) The user may optionally pass one or more frame texts to scope the summary; without one, default behaviour applies. Mode is auto-detected (Step 1), so the user need not say which.

## When not to invoke

- The user asks a research question. Use `query`.
- The user wants to remove existing wiki content. Use `forget`.
- The user wants to replace content while preserving the old view (a swap/merge/split decided in advance). Use `supersede`.
- The user wants to re-verify an existing page against its raw source without rewriting it. Use `audit`. (In ingest, "refresh" means re-reading the raw and rewriting the page in place — a reingest — not re-verification.)
- The user wants a source captured into an external structured database (a project-specific field set) rather than the wiki. If the project defines a capture skill for that destination, use it. `ingest` instead builds **wiki** pages — a full source page plus the atomic, reusable concept/entity pages it supports — all source-grounded and interlinked. (The difference is destination and form, not depth.)

## Procedure

```text
Ingest Progress:
- [ ] Step 1: Load orientation; detect mode (new/existing, depth); confirm reason/purpose and frame; (book) settle read range before the Step 2 read
- [ ] Step 2: Read the source (confirm full-text coverage; for a book, its scoped range)
- [ ] Step 3: Surface the plan via per-decision AskUserQuestion calls
- [ ] Pre-write gate: confirm a clean working tree for every pre-existing page/attachment this run will overwrite (both modes); do any approved legacy rename — before Step 4
- [ ] Step 4: Extract or prepare approved attachments
- [ ] Step 5: Write or update the source page
- [ ] Step 6: Draft or update concept/entity (and synthesis) page changes
- [ ] Step 7: Apply approved edits; cascade needs-update (existing mode)
- [ ] Step 8: Check the claims (refuter-backed), self-check the pages, set status (see .claude/skills/multi-skill/references/verification.md)
- [ ] Step 9: Compile the Recommended next ingests report section
- [ ] Step 10: Update hot.md
- [ ] Step 11: Prepend log.md
```

1. **Load orientation; detect mode; confirm reason/purpose and frame.** Read `1-wiki/hot.md`, `1-wiki/index.md`, `.claude/skills/ingest/ingest-memory.md`, and `.claude/skills/multi-skill/multi-skill-memory.md` if not already loaded this session. Use hot/index to avoid duplicate concept/entity pages and to identify related notes and near-duplicates. Apply prior memory corrections about scope, framing, and source-supportedness before drafting.

   Then settle the mode:
   - **Resolve the stem first.** If the user did not give the exact raw filename, resolve `{stem}` from `0-raw/` and confirm it before the existence check (see Edge Cases) — the confirmed stem drives new/existing detection.
   - **New vs. existing:** does `1-wiki/sources/{stem}.md` exist? If yes → existing-source (reingest) mode. If no → new-source mode. Before concluding "new," rule out a legacy page mapping to this raw under a different name: grep `1-wiki/sources/` for any page whose `file:` points at this raw, and scan for case- or kebab-variants of the stem, anchoring both greps on the stem's extension / wikilink-closing delimiter so a prefix-of-a-longer-stem neighbour does not mis-match (regex mechanics: `.claude/skills/multi-skill/references/inbound-reference-discovery.md`). Eyeball each hit. A match is existing mode and a rename candidate for Step 3, not new — skipping this check silently creates a duplicate source page and abandons the prior view, the hardest ingest error to reverse. Retain the grep run and its hits (or "no match") for the Step 8 report; an unretained check is treated as not-run. When the page does exist, confirm its `file:` resolves to the exact raw named: the stem drops extension and subdirectory, so `0-raw/papers/{stem}.pdf` and `0-raw/articles/{stem}.md` both map to `1-wiki/sources/{stem}.md`. A `file:` pointing at a different raw is a stem collision, not a reingest — surface it via `AskUserQuestion` rather than silently re-reading the other raw in Step 2.
   - **Depth:** normal unless the user opts into deep. **Do not infer deep from the source or the request's tone — ask.** If the user's request did not already specify the depth, ask once with `AskUserQuestion`, describing both modes for a reader who knows nothing about them. Recommended wording: `"Normal or deep ingest? Normal gives a high-level orientation — the key claims and where the evidence lives — and stays compact. Deep produces a reference-grade source page: equations, hyperparameters, full result tables, and careful figure/page references, so it can support writing or serve as a long-term reference. Deep takes longer and the page is much larger, and you must say what the depth is for. Concept/entity pages stay short and atomic either way."` Options: `Normal` / `Deep`. Honour an explicit request ("deep ingest", "reference-grade") without re-asking.
     - **Deep requires a stated depth purpose** — what the depth is for (a frame, a paper section the page will support, a specific question, a paper being written). A frame is the purpose only when it is a genuine scope — a section, a question, or a concrete future use; echo it back. A bare topic word (e.g. "transformers") is not a scope — treat it like "thorough" and ask for the non-frame purpose. Without a frame, ask for the non-frame purpose before reading. Do not accept "thorough" or "long-term reference." If the user can't give a purpose after one focused ask, fall back to normal and proceed. Capture it: a frame goes in the `frames:` list at write time; a non-frame purpose goes in the report's `purpose:` field (not on the page).
     - **Existing-source mode never auto-instigates deep** — settle the reingest reason and frame first; switch to deep only via the same explicit ask (`references/existing-mode.md`).
   - **Books — settle the read range before reading (books only).** A book (`type: book`, a raw under `0-raw/books/`) is the one source not read cover to cover, because it is large and usually only a single chapter is wanted. Before the Step 2 read, ask via `AskUserQuestion` which chapter or page range to ingest — offer the specific range and "the whole book" as options; the range itself is free-form (`ch. 3`, `pp. 40–72`, `sec. 2.1–2.4`). The chosen range is the read unit: Step 2 reads it *in full* (the range replaces "the whole file" — not a licence to skim), and Step 8 coverage-checks against that range, not the whole book. The book's source page is the usual `{stem}.md` (the stem matching the raw, as for any source), scoped to that range; name the chapter or section in `title:` (`CLAUDE.md` → Source pages). A frame, if also given, still scopes what gets *written* within that range — the range and the frame are different axes. In existing-source mode, reuse the page's recorded range (named in `title:`), re-asking only to change it.
   - **Existing-source mode only — confirm the reason, then run the always-on checks** in `references/existing-mode.md`: the reingest reason (no reason given → ask, since a reingest without one creates drift), the `needs-update` / `*[tentative]*`-resolution checks, the schema-migration check against the page and its dependents, the frames decision (reuse / append / clear, with its scope-widening test), and the deep-purpose recovery. Locate every dependent — every page listing this source in `sources:` — so Step 7's cascade can reach it.

2. **Read the source in full (confirm full-text coverage).** Read the raw file from `0-raw/` (use the existing page's `file:` frontmatter to find it in existing mode). **Every ingest — new, existing, normal, or deep — fully reads the raw, cover to cover. There is no targeted partial re-read; the reason, frames, and depth control what gets written, never how much gets read. The one exception is a book (`type: book`), whose read unit is the chapter or page range settled in Step 1: read that range in full (cover to cover within the range, never a skim), not the whole book.** Deep mode reads the same unit and additionally goes deeper on the equations/figures/tables the depth purpose needs; out-of-scope sections within the unit are still read, just written only as the scope admits. When one source would make an oversized page, propose chapter-level source pages instead (each split unit still read cover to cover) — only a book is scoped by an up-front range prompt. If frames are in effect, read through them as well, keeping both the framed and a general read in mind. **Read critically as well as comprehendingly (Darwin's golden rule):** on sight, capture what cuts against the source's claims, the assumptions it leaves unstated, and the strongest sceptical critique — disconfirming evidence escapes attention unless caught as you read; when a frame is active, also ask what cuts against the frame's thesis (a positive lens must not become confirmation-seeking). These feed `Assumptions`, `Appraisal`, and concept-page `Disconfirming Evidence`, and `Contradictions` where they bear on scope. **Confirm full-text coverage before drafting** by a positive probe, not a vibe: the final page/section — for a book, the final page of the chosen range — is present and intelligible (catches truncation) and body text, not only figure captions, is extractable (catches an image-only scan or abstract-only paywall). For an image- or media-based raw, confirm instead that the visual content the page draws on (every slide, frame, figure) is present and legible. If coverage is partial, surface it in the planning step and draft only what is covered — never summarize partial content as the whole source. If the source's relevance is unclear, see Edge Cases before drafting.

   **Register the raw's pagination before any locator is written (PDF raws).** What a page prints (`p. M`) is a fact about the raw, not derivable by rule — an appendix may restart numbering, a proceedings build may start high, a body may print no number — and getting it wrong yields a confidently-wrong citation that passes every structural check. Record it once per raw in `.claude/skills/multi-skill/pagination-map.md`, using `.claude/skills/multi-skill/scripts/pagination_map.py` to propose the map from the raw's footers and then confirming every line against a rendered footer crop. The exact commands, the confirm-every-line rule, and the unregistered-raw fallback are in `references/pagination.md`.

3. **Surface the plan via per-decision `AskUserQuestion` calls.** Post a single chat context message first — the full slate, so the sequence is no surprise and the user can pre-empt whole classes in chat ("just the obvious concepts, skip the images") — then ask each decision through its own call: one per call, never batched, framed include / drop / other, the recommended option marked `(Recommended)` and first. The decision types below are not a fixed question count — types 1, 2, 6, and 8 fire once per candidate, so a dense paper expands to 10–20 calls. Do not collapse per-candidate questions into one summary to save calls; the only sanctioned shortcut is the user pre-approving or pre-skipping whole classes in chat. Step 3 is complete only when every decision type with at least one candidate has fired — including the easy-to-skip contradiction (type 6) and relationship-sweep (type 8) questions; do not advance to Step 4 with mapped-but-unasked relationships or contradictions outstanding.

   The context-post catalogue (frame echo, takeaways, sibling back-references, contradiction cross-check, relationship sweep, retrieval tags, disconfirming evidence) and the per-decision question types (the emphasis question, then membership questions 1–10) are in `references/planning-questions.md` — work the plan through it, one `AskUserQuestion` call per decision.
   Only approved items become wiki content. Do not act on partial answers. If the user pauses mid-sequence, wait; on resume, keep the answers already given and continue from the next unanswered decision (do not re-ask answered ones or discard them).

4. **Extract or prepare approved attachments.** Write each approved image to `1-wiki/attachments/{stem}/{name}.png` (create the folder if needed). Tools:
   - PDFs: `pdftoppm -png -r 300 -singlefile -f {page} -l {page} "{raw}" {outprefix}` renders one page to `{outprefix}.png` (300 DPI per `CLAUDE.md` → Attachments). `references/attachments.md` covers the `-singlefile` naming caveat, the `pdfimages` embedded-raster path with its indexed-name/`.ppm` rename fixups (rename to the approved `{name}.png` before embedding, or the Step 5 embed dangles), the preferred PyMuPDF point-space clip, and the render→inspect→crop loop.
   - Non-PDF media already in `0-raw/media/`: copy or symlink into `1-wiki/attachments/{stem}/`. If the copy fails (missing or unreadable file), report it and ask rather than leaving a dangling embed.
   - **Existing mode:** these mutations run only after the Step 5 clean-working-tree gate and any approved legacy rename (a `replace`/`remove` overwrites or moves a committed attachment). `add`/`replace` write as above. When a `replace` changes the image *content* (a corrected figure, not a tighter crop or higher DPI), treat every page embedding that path as a dependent — grep the embed path `1-wiki/attachments/{stem}/{name}` across all of `1-wiki/` (a path-qualified embed can be reused by a page under a different stem, so not only this source's `sources:` dependents) and, on a `verified` embedding page whose non-obvious claim the image backs, mark that claim `*[unverified]*` (the body text is byte-identical, so `verified_hash` does not move and lint cannot catch a missing mark; mandatory, mirrors `supersede`, `dependent-cascade.md`). `remove` quarantines the file to `2-outputs/forget/quarantine/attachments/{stem}/{name}.png` per `.claude/skills/multi-skill/references/quarantine-path-convention.md` (the `cmp -s` byte-identity check, the `git check-ignore -q` guard, and the `-N` name-clash suffix rule) — never delete outright, so the prior view is preserved.
   - Never write into `0-raw/`. If extraction fails (encrypted PDF, vector-only figure), report it instead of silently skipping, and put the fallback to the user as a fresh `AskUserQuestion` (the Step 3 approval assumed a clean extraction that did not materialize): drop the embed, accept a locator-only reference, try a different render, or place a manual screenshot. A dropped embed must also be removed from the Step 5 write plan and never written to `attachments:` or embedded in the body, or Step 8 catches it as a dangling embed.

5. **Write or update the source page** at `1-wiki/sources/{stem}.md`. Use the source-page frontmatter and required callouts from `CLAUDE.md`. Every callout carries a block ID — the kebab-case of its display title — as the last line inside the `>` block (`> ^tldr`, `> ^evidence`, …; no blank `>` line before it; `CLAUDE.md` → Callout block IDs), on every callout including empty placeholders and any inserted by the schema-migration check. For PDF raws, every page locator in `Evidence`/`Method` (and any quoted in `Key Claims`/`TL;DR`) carries a `#page=N` deep-link with the structural anchor and page **together inside** the display: `[[0-raw/papers/{stem}.pdf#page=5|sec. 3, p. 5]]` (never split the anchor outside the link or leave a page-only display — lint `source_locator_incomplete`). Cite abstract-drawn content `abstract, p. 1`, never relabelled `sec. 1`. Non-PDF raws use the per-type locator formats and link the raw without a `#page=N` anchor. `N` is the physical PDF page; read `p. M` off the pagination map registered in Step 2 rather than re-deriving an offset a restarting appendix would defeat, and where the map says a page prints nothing, drop `p. M` and cite the anchor alone (`CLAUDE.md` → Source support and verification). Worked examples and the figure-crop loop are in `references/attachments.md`.
   - **New:** write the full page, its status settled in Step 8 by what the claim check establishes. `file:` points at the raw path-qualified into `0-raw/` (`file: "[[0-raw/papers/<bibkey>.pdf]]"`); authors use pipe-rendered display, auto-linking any author already in `1-wiki/entities/` and leaving a one-off collaborator with no page as a dangling path-qualified `authors:` wikilink (a new author page is proposed only via a Step 3 create-new question, and only for a prominent author — `CLAUDE.md` → Author page creation policy).
   - **Clean-tree gate — both modes, before Step 4's attachment mutations and any page write.** Confirm a clean working tree for every *pre-existing* file this run will overwrite: the source page (existing mode), every dependent the Step 7 cascade will touch (located in Step 1), and every pre-existing concept/entity page a Step 6 edit will touch — attach-to-existing, reciprocal `Contradictions`, sibling back-reference — which occur in **new** mode too and were previously ungated; plus, on a rename, the legacy page and its attachments folder. `git status --short` each path; if any is dirty, surface via `AskUserQuestion` (proceed / commit-or-stash first / abort) — an uncommitted prior edit is lost silently on overwrite and git history is the only preserved prior view (ingest does not snapshot to `2-outputs/`; `CLAUDE.md` Safety: never overwrite silently). Brand-new pages have no committed prior view and are not gated.
   - **Existing:** if Step 3 approved a legacy-page rename, then — working tree confirmed clean — `git mv` the legacy page `1-wiki/sources/{legacy}.md` → `1-wiki/sources/{stem}.md` and its attachments folder `1-wiki/attachments/{legacy}/` → `1-wiki/attachments/{stem}/`, and rewrite every inbound reference per `.claude/skills/multi-skill/references/inbound-reference-discovery.md`, before any write — otherwise the write lands a fresh `{stem}.md` beside the untouched legacy page, re-creating the duplicate the Step 1 guard exists to prevent. Then preserve `type:`, `file:`, and `created:`; touch `updated:`. Apply the Step 1 schema-migration check — insert each missing required callout in its correct position from `CLAUDE.md`, filling from the raw where the scope makes that natural, otherwise the empty placeholder. Sync `attachments:` with the current files (drop entries for quarantined files). Keep `Concepts and Entities` synchronized. Fold any stale Figures callout's embeds into `Evidence`/`Method` and drop it.
   - **Frames frontmatter:** record each frame as an item in the `frames:` list; in existing mode apply the Step 1 frames decision (reuse / append / clear, with its scope-widening consequence — a genuine widening grows the body and resets `status: draft`). `frames:` is always present — write `frames: []` when unscoped, never omit it — and appears in frontmatter only, never in the page body.
   - **Sections are not quotas.** Fill only with genuine, source-grounded content within the frames/purpose; leave `> - None noted` otherwise.
   - **Re-voice every bullet; never copy the source's sentences.** A source page is an evidence record in the user's own words, not a copy-paste of the raw. Write each bullet from the idea you carried away, changing sentence structure and clause order — not by swapping synonyms into the source's sentence, which stays lifted. Verbatim wording is allowed **only** inside quote marks paired with a locator, and only for the load-bearing `Evidence` anchor a Key Claim needs. Self-check: a bullet a reader could find by searching the raw is not yet re-voiced. This is draft-time discipline (Step 8's paraphrase-versus-extraction check is only the backstop) — details in `references/source-page-writing.md`.
   - Per-callout writing guidance (what genuinely belongs in each of `TL;DR`, `Contribution`, `Key Claims`, `Evidence`, `Method`, `Assumptions`, `Limitations`, `Appraisal`, `Concepts and Entities`, `Contradictions`, `Open Questions`, `Connections`), the inline-embed format, and the citation / `attachments:` / no-bold rules are in `references/source-page-writing.md`.

6. **Draft or update concept/entity (and synthesis) page changes.**
   - For each approved concept/entity page, apply the one-idea test: one idea or named thing? explained simply? reusable for later writing? reads standalone with its source page closed? supported by at least one source page? connects to existing notes?
   - Existing page: a small edit (usually 1–3 bullets or a tighter `Idea`). New page: the full concept/entity template from `CLAUDE.md`, its status settled in Step 8, with `aliases:` populated when the source gives the concept a genuine acronym, alternate name, or older term (e.g. `aliases: [Adam]` on an Adaptive Moment Estimation page — `CLAUDE.md` → Concepts and entities) and on a same-as merge, otherwise `aliases: []`, each callout ending in its block ID — the kebab-case of its display title, so `[!why]` Why It Matters takes `> ^why-it-matters` (`> ^idea`, `> ^why-it-matters`, …; see `CLAUDE.md` → Callout block IDs). Only fill sections with genuine content (sections are not quotas) — a new page often earns only `Idea`, `Why It Matters`, `Sources`; the rest stay `> - None yet`.
   - At most one defining image per page, embedded in `Idea`, illustrating the idea (not summarizing the source); never in `Examples`. Deep mode: do not push equations, metric tables, or long method detail into concept/entity pages unless the page is explicitly about that idea.
   - Add the source to `sources:` (`- "[[1-wiki/sources/{stem}.md|{stem}]]"`) and the `Sources` callout. Cite each non-obvious factual claim inline to the specific source it draws from, in one of the two canonical forms (`CLAUDE.md` → Source support and verification is the authority); leave obvious/definitional bullets and own-voice judgement uncited — not citation wallpaper. Three rules bite hardest at drafting time. **Never fabricate a locator:** if you cannot confirm the page or section in the raw, mark the claim `*[unverified]*` / `*[tentative]*` or quote-and-locate only what you can confirm — a plausible but wrong `#page=N` is worse than an honest gap. **On a bullet naming two or more sources** (the cross-source callouts — `Contradictions`, `Not This`, `Disconfirming Evidence`, synthesis `Tensions`), cite each clause to the source that states it, not the source the bullet is framed about: a contrast sentence has two origins and two locators, and a true claim from source A pinned to a locator in source B passes every structural check, so only opening the cited page catches it. **Carry the reason, never a fabricated mechanism:** a causal/comparative/evaluative claim gives its source's reason, or is recast as own-voice, or flagged `*[tentative]*` where the source gives none. Wikilink every genuine reference to an existing page, on every occurrence; a page never links to itself. See also `CLAUDE.md` → Plain-language style and Wikilink format.
   - Synthesis pages (existing mode): keep the cross-source answer, evidence map, tensions, and source list; update embeds the same way. ingest only updates an existing synthesis whose source list this source already belongs to; it never creates a synthesis page — that is `synthesis`'s job. A source that strengthens a new multi-source cluster is surfaced as a synthesis candidate in Step 3, not authored here.

7. **Apply approved edits; cascade (existing mode).** Mechanical fields need no separate approval: `created:` (new pages), `updated:` (touched pages), `source_count:` to match `sources:`, `attachments:` to match files, `Concepts and Entities` callout updates, and `1-wiki/index.md` entries for new/renamed pages.
   - **Existing mode — cascade `needs-update`.** Walk every dependent (located in Step 1) and apply the shared dependent-cascade mechanics in `.claude/skills/multi-skill/references/dependent-cascade.md` — what a dependent is, the `needs_update_reason:` hand-off and append-don't-overwrite rule, `source_count`/`Sources` sync, the `verified_hash` strip on demotion, and the zero/single-source guards. In ingest, **material** means a deeper read corrects a claim the dependent built on, adds a contradiction it doesn't track, or revises an interpretation it inherited — set the dependent `status: needs-update` with the hand-off reason (e.g. `needs_update_reason: inherited the pre-correction claim from {stem}; reingest revised it — re-check the Key Claims figure against {stem} Evidence and update or drop`); **additive-only** (extra evidence, fixed typos, still-correct fuller write-up, attachment adds) does not cascade — touch `updated:` only on dependents whose `Sources` callout changed mechanically. When the cascade adds or changes a claim on a `verified` dependent, apply the status/marker rules from Conventions (Recap): a non-material **added** claim is marked `*[unverified]*` (the dependent stays `verified` with that pending delta); a **changed** verified claim demotes it to `draft`.
   - **Existing mode — schema-migration to dependents.** For each dependent flagged in Step 1 as missing callouts, insert them in correct position as empty placeholders (`> - None yet`); do not fill from the source page unless the scope naturally produces the content. Remove obsolete line-by-line citation style when encountered. Update `sources:` and `source_count`. Preserve contradictions.

8. **Check the claims, self-check the pages, set the status.** Run all three from the shared spec `.claude/skills/multi-skill/references/verification.md`, which defines each in full:

   - **The claim check** (mandatory, refuter-backed, scoped to exactly the claims this run wrote or changed) — its three questions asked of each claim against the raw still open, refuters spawned read-only from this top-level agent at the tier the claim's impact sets, every quote a refuter returns re-grepped before acting on it. Record the one late-section raw detail re-located and the one `#page=N` spot-checked (or `n/a` for a non-PDF): a check recording neither has not re-read the raw, and the ingest is not complete. Open every locator on a cross-source bullet — no sampling, since a mis-located citation hides behind a good sibling. Any mid-run citation fix triggers the repeated-literal sweep across `1-wiki/`; record it. Re-run on any fix, bounded to three rounds (stop and report on non-convergence or an oscillation rather than looping).
   - **The page self-check** (light, no refuters, non-blocking) — each touched page read as a page. Fix what is cheap and local; record what needs the whole page or the wiki to settle as a hand-off to `audit`, specific enough to act on without rediscovery.
   - **Set each page's status** by the spec's Setting Status rule, and say so in the report. Confirm condition 3 yourself — run `python3 .claude/skills/multi-skill/scripts/check_wiki.py "1-wiki"` and scope its JSON to the page being stamped, since the script reports the whole tree. A page absent from that output was not scanned at all rather than found clean, so confirm it was on disk when the script ran. Then stamp `verified_hash:` with `python3 .claude/skills/multi-skill/scripts/body_hash.py {page}`, never by hand. Apply the reach and marker rules from Conventions (Recap). Because lint is structural it cannot catch a `frames:` widening that fails to grow the body — the claim check is that guard, and an uncovered widening blocks `verified`.

   The spec also routes the report — both modes write `2-outputs/ingest/ingest-YYYY-MM-DD-HHMM-{stem}.md` (new-source or reingest shape) recording frames/purpose, the claim tally, the hand-offs, and the status set; its `Recommended next ingests` section is compiled in Step 9.

9. **Compile the `Recommended next ingests` report section.** Close the Step 8 report with it: the papers that would fill a gap this ingest surfaced — a single-source page it created or left wanting its primary, a watch item it added, a dangling concept that now warrants its own source, or uningested prior work this source leans on. One entry per paper: author and year, title, and one line on the gap it fills. Ingest-derived, not a generic literature dump. List only papers you are confident genuinely exist — never fabricate a title, author, or venue (mark an uncertain one `(verify exists)`); write `none` when nothing specific surfaced (not a quota — do not pad it). Report shapes and the honesty guard: `.claude/skills/multi-skill/references/verification.md`.

10. **Update `1-wiki/hot.md`.** Reuse the single 24-hour UTC stamp from `TZ='UTC' date '+%Y-%m-%d-%H%M'` across the Step 8 report filename, this bullet, and the Step 11 log heading (one stamp, not re-fetched per step, never a bare `date` — a re-fetch drifts them across a minute boundary).
   - Prepend Recent activity: `- [YYYY-MM-DD HH:MM] {ingest | ingest-deep | reingest} | {stem}` (verb by mode).
   - Add new low-coverage, `needs-update`, and contradiction-bearing concept/entity or synthesis pages to Open threads (pipe-rendered wikilinks).
   - Never edit Active focus unless explicitly asked.

## Edge cases

- **Ambiguous or missing filename.** If the user names a source without its exact raw filename (e.g. "ingest the attention paper"), resolve the `{stem}` from `0-raw/` and confirm it before reading. The resolved stem also determines new vs. existing mode (Step 1).
- **No durable idea (new).** Create only the source page; do not invent concept/entity pages.
- **Near-duplicate concept/entity page.** Update the existing note instead of creating a new one.
- **Contradiction.** Preserve both sides in `Contradictions`; set affected concept/entity or synthesis pages to `needs-update`.
- **Source relevance is unclear.** Use `AskUserQuestion` to ask whether to ingest, skip, or file only a minimal source page.
- **No frame provided.** Default to unscoped: generate your own takeaways and contribution; no missed/adjacent buckets surface.
- **Frame provided but the paper doesn't fit it.** Say so in Step 3 before any questions, via one `AskUserQuestion` with three options: (a) widen the frame, (b) drop the frame and ingest unscoped, (c) skip the source.
- **Deep ingest without a purpose.** Ask before reading; fall back to normal mode if the user can't articulate one.
- **Existing mode — reingest reveals a new reusable idea.** Propose it; do not create it without approval.
- **Existing mode — a reingest landed wrong and needs reverting.** The prior committed page view is in git (ingest does not snapshot to `2-outputs/`): restore it with `git checkout <sha> -- 1-wiki/sources/{stem}.md`, then reverse this run's cascade — walk the Step 7 dependents and strip only the `needs_update_reason:` clause this run appended, preserving any prior hand-off (`dependent-cascade.md` append rule). Also restore any attachment this run quarantined (from `2-outputs/forget/quarantine/attachments/{stem}/`), and remove the pages plus the `index.md`/`hot.md`/`log.md` entries this run added — or `forget` them, since `git checkout <sha>` cannot delete files that did not exist at `<sha>`. A new-mode ingest that landed wrong is reversed by `forget` on the source page and every concept/entity page it created. Uncommitted prior edits are not recoverable, which is why Step 5 gates on a clean working tree.
- **Existing mode — reingest weakens support for a dependent.** Mark it `needs-update` or remove the source from its support list after approval. If the dependent is a synthesis and removing this source drops it below two sources, do not leave it lint-failing: surface forget's stub-or-remove decision via `AskUserQuestion` — set `single_source_stub: true` (deliberate stub), re-source it, or quarantine it (`forget`) — and write a precise `needs_update_reason:` if it stays under-supported.
- **Existing mode — saved frames no longer fit the reason** (e.g. a contradiction outside every frame). Surface it in Step 3; per the Step 1 frames rule the user can keep the frames (item stays out of scope), append a lens that admits it, or clear to unscoped.
- **Existing mode — existing attachment is fine.** Default `keep`: no extraction, no embed change.
- **Concept/entity page would exceed one idea, or evidence is too dense.** Split the page; keep dense evidence in the source page (split by section if needed).
- **Image extraction fails.** Report it in Step 4; offer a locator-only reference, a different render, or a manual screenshot the user places in `1-wiki/attachments/{stem}/`.
- **The user only needs a few missing details on an existing page.** That is existing-source mode with reason `missed evidence` — a full re-read with a targeted write, not a full deep pass.

## Limits

- One source per invocation.
- Never modify `0-raw/`. Image extraction writes only to `1-wiki/attachments/{stem}/`; removed attachments go to `2-outputs/forget/quarantine/attachments/{stem}/` (never deleted outright).
- Concept/entity pages stay atomic and short; deep detail belongs in source pages unless it is itself the reusable idea (the one-defining-image cap is Step 6's, not restated here).
- Frames and the depth purpose scope the source page only, never the concept/entity pages (which stay reusable across future framings). The remaining cross-cutting rules are stated once upstream, not re-argued here: deep requires a stated purpose (Depth), sections are not quotas (Purpose), no bold or italic and pipe-rendered `.md` wikilinks (Conventions).
- Ingest certifies claims, not pages. It may set a page `verified` on its claim check, but does not judge the page as a page — those findings go to `audit` as recorded hand-offs. Never withhold `verified` because one is open, and never settle one by splitting, merging, or rewriting.
- Certification does not reach past the raw this run read. A claim cited to another source is left as it stands or marked `*[unverified]*` — never certified on the strength of the page's other citations.
