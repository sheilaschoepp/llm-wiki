# ingest

Process one raw source into a source page, then create or update the concept/entity pages it supports. One skill, three composable modes — **new vs. existing** (auto-detected by whether `1-wiki/sources/{stem}.md` exists), **normal vs. deep** (source-page depth), and optional **frames** (angles scoping the page) — composing on one shared spine (read → write/update the source page → create/update concept-entity pages → verify). What each mode adds:

| Mode | What it adds to the spine |
|---|---|
| New (default) | Create the source page first-time; propose new concept/entity pages; add index entries. |
| Existing (page exists) | Confirm a reason; run the always-on checks (`references/existing-mode.md`); attachment keep/replace/remove/add; cascade `needs-update` to dependents; preserve `created:`. |
| Normal depth (default) | High-level orientation only. |
| Deep (explicit opt-in) | Reference-grade source page (equations, hyperparameters, tables, more figures, deeper Method/Appraisal) within a stated purpose. Concept/entity pages stay atomic. |
| Frames (optional) | Scope every source-page section to the frames' union; save each to `frames:`. |

## Purpose

The source page preserves what this source contributes and where the exact evidence lives. Concept/entity pages capture reusable ideas in simple language — do not turn them into source summaries.

**New vs. existing source (auto-detect)** — detected in Step 1 by whether `1-wiki/sources/{stem}.md` exists; the table above says what each mode adds. Existing updates the evidence layer without bloating concept/entity pages into source summaries — but "bloat" is source-summary detail, not source support, so attaching a genuinely-supporting source and the claims it contributes (including to a page the re-read newly reveals it supports) is maintaining the cross-source record, not bloat. Terminology: "update" = any in-place modification; "refresh" = a reingest (of any reason), of which `schema refresh` is one named reason.

**Depth.** Default normal; deep is an explicit opt-in Step 1 asks about, never inferred from the source or the request's tone. Deep — the longest-lasting page in the wiki and the easiest to bloat — **requires a stated depth purpose**: what the depth is *for* (a frame, a paper section the page will support, a specific question, a paper being written). "I want a thorough page" is not a purpose; it produces an indiscriminate source dump. Deep expands the *depth* of in-scope sections, never the breadth of out-of-scope ones, and never the concept/entity pages (which stay one-idea and simple regardless). Throughout, `ingest-deep` is the verb token used in log and hot entries.

**Frames are the ceiling, not a starting point.** A frame (lens, angle) is one positive scope on the source page — "only the attention-efficiency results", "the optimizer-convergence proof" — and `frames:` may hold several, the page scoped to their union. Sections no frame admits stay at the empty placeholder (`> - None noted`), never filled from outside the frames even when the source supports it. The raw is still fully read (Step 2), and Step 8 judges the page against the frames' union (or deep purpose), not the whole source — a thin page under a narrow frame is the correct outcome. In deep mode a frame, when given, *is* the depth purpose. A frame is a positive lens, never a hard exclusion, so reframing only ever *adds*; the reuse / append / clear decision and its scope-widening test are in `references/existing-mode.md`.

**A frame may be a pre-applied analysis layer.** When the frame is a categorization the user already attached to the source (tags, a typology, a labelling scheme), treat those labels as the user's analysis layer, not facts about the source: assess each against what the source actually does — never copy them verbatim as characterizations, never blanket-reject them. The page stays grounded in the source's own language, not the frame's vocabulary. (Project-specific frame conventions live in `ingest-memory.md`.)

**Sections are not quotas.** Every required callout appears, but not all need content: a section with nothing genuine and source-supported to say keeps its empty placeholder (`> - None noted` on source pages, `> - None yet` on concept/entity pages). Several placeholders is the correct outcome when the source earns nothing there. Do not invent, paraphrase, or pad. Deep ingest expands the depth of filled sections, not their count.

**Pattern: analyze → plan → validate → execute → verify.** Step 2 analyzes (reads the source); Step 3 plans and validates (batched `AskUserQuestion`, user approval the gate); Steps 4–7 execute only approved edits; Step 8 verifies (two independent packets — factual accuracy, clarity).

**Verification stands in for human re-voicing.** The smart-note method has a human re-voice the note at a commit point; this wiki keeps pages LLM-drafted at `status: draft`, so the Step 8 packets plus a later `audit` are load-bearing, not optional.

## Conventions (Recap)

The shared `CLAUDE.md` rules this skill leans on are recapped in `references/conventions.md`: source-page filename stems, path-qualified pipe-rendered wikilinks, the bold and italic ban in wiki content, the `AskUserQuestion` batching rule, where structural authority lives, and the status and marker rules this skill applies to a `verified` page. Read it at Step 1, before the first decision or write; Steps 7 and 8 apply its status and marker rules.

## When To Invoke

Use when the user names or identifies a specific raw source under `0-raw/` and asks to ingest, process, capture, digest, import, deep-ingest, reingest, or refresh it. Implicit phrasings count too (the description lists them). The user may optionally pass one or more frame texts to scope the summary; without one, default behaviour applies. Mode is auto-detected (Step 1), so the user need not say which.

## When Not To Invoke

- The user asks a research question. Use `query`.
- The user wants to remove existing wiki content. Use `forget`.
- The user wants to replace content while preserving the old view (a swap/merge/split decided in advance). Use `supersede`.
- The user wants to re-verify an existing page against its raw source without rewriting it. Use `audit`. (In ingest, "refresh" means re-reading the raw and rewriting the page in place — a reingest — not re-verification.)

## Procedure

```text
Ingest Progress:
- [ ] Step 1: Load orientation; detect mode (new/existing, depth); confirm reason/purpose and frame; (book) settle read range before the Step 2 read
- [ ] Step 2: Read the source (confirm full-text coverage; for a book, its scoped range); register the raw's pagination map (PDF)
- [ ] Step 3: Surface the plan via AskUserQuestion, batched as far as the decisions allow
- [ ] Step 4: Clean-tree gate (both modes) and any approved legacy rename; extract or prepare approved attachments
- [ ] Step 5: Write or update the source page
- [ ] Step 6: Draft or update concept/entity (and synthesis) page changes
- [ ] Step 7: Apply approved edits; cascade needs-update (existing mode)
- [ ] Step 8: Run ingest verification (see .claude/skills/multi-skill/references/verification.md); write the report, closing with Recommended next ingests and the Self-report
- [ ] Step 9: Update hot.md
- [ ] Step 10: Prepend log.md
```

1. **Load orientation; detect mode; confirm reason/purpose and frame.** Read `1-wiki/hot.md`, `1-wiki/index.md`, `.claude/skills/ingest/ingest-memory.md`, and `.claude/skills/multi-skill/multi-skill-memory.md` if not already loaded this session. Use hot/index to avoid duplicate concept/entity pages and to identify related notes and near-duplicates. Apply prior memory corrections about scope, framing, and source-supportedness before drafting.

   Then settle the mode:
   - **Resolve the stem first.** If the user did not give the exact raw filename, resolve `{stem}` from `0-raw/` and confirm it before the existence check (see Edge Cases) — the confirmed stem drives new/existing detection.
   - **New vs. existing:** does `1-wiki/sources/{stem}.md` exist? If yes → existing-source (reingest) mode. If no → new-source mode. Before concluding "new," also rule out a legacy page that maps to this raw under a different name: grep `1-wiki/sources/` for any page whose `file:` frontmatter points at this raw file, and scan the directory for case- or kebab-variants of the stem — anchor both greps per `.claude/skills/multi-skill/references/inbound-reference-discovery.md` so a prefix-of-a-longer-stem neighbour does not mis-match, and eyeball each hit to confirm it maps to this exact raw. A match is existing mode and a rename candidate for Step 3, not new — skipping this check silently creates a duplicate source page and abandons the prior view, the hardest ingest error to reverse. Retain the grep run and its hits (or "no match") to record in the Step 8 report; new-source mode is not entered until this check is run and its result retained — an unretained check is treated as not-run (mirroring Step 8's proof-of-re-read gate). When `1-wiki/sources/{stem}.md` does exist, before concluding reingest, confirm its `file:` frontmatter resolves to the exact raw the user named: the stem drops both extension and subdirectory (Conventions), so `0-raw/papers/{stem}.pdf` and `0-raw/articles/{stem}.md` both map to `1-wiki/sources/{stem}.md`, and if the existing page's `file:` points at a different raw this is a stem collision, not a reingest — surface it via `AskUserQuestion` (same stem, different sources) rather than silently re-reading the other raw's `file:` in Step 2.
   - **Depth:** normal unless the user opts into deep. **Do not infer deep from the source or the request's tone — ask.** If the user's request did not already specify the depth, ask once with `AskUserQuestion` (options `Normal` / `Deep`), describing both for a reader who knows nothing about them: normal is a compact high-level orientation; deep is reference-grade (equations, hyperparameters, full result tables, careful figure/page references), takes longer, produces a much larger page, and requires a stated purpose. Say that concept/entity pages stay short and atomic either way. Honour an explicit request ("deep ingest", "reference-grade") without re-asking.
     - **Deep requires a stated depth purpose** — what the depth is for (a frame, a paper section the page will support, a specific question, a paper being written). A frame is the purpose only when it is a genuine scope — a section, a question, or a concrete future use; echo it back. A bare topic word (e.g. "transformers") is not a scope — treat it like "thorough" and ask for the non-frame purpose. Without a frame, ask for the non-frame purpose before reading. Do not accept "thorough" or "long-term reference." If the user can't give a purpose after one focused ask, fall back to normal and proceed. Capture it: a frame goes in the `frames:` list at write time; a non-frame purpose goes in the report's `purpose:` field (not on the page).
     - **Existing-source mode never auto-instigates deep** — settle the reingest reason and frame first; switch to deep only via the same explicit ask (`references/existing-mode.md`).
   - **Books — settle the read range before reading (books only).** A book (`type: book`, a raw under `0-raw/books/`) is the one source not read cover to cover, because it is large and usually only a single chapter is wanted. Before the Step 2 read, ask via `AskUserQuestion` which chapter or page range to ingest — offer the specific range and "the whole book" as options; the range itself is free-form (`ch. 3`, `pp. 40–72`, `sec. 2.1–2.4`). The chosen range is the read unit: Step 2 reads it *in full* (the range replaces "the whole file" — not a licence to skim), and Step 8 coverage-checks against that range, not the whole book. The book's source page is the usual `{stem}.md` (the stem matching the raw, as for any source), scoped to that range; name the chapter or section in `title:` (`CLAUDE.md` → Source Pages). A frame, if also given, still scopes what gets *written* within that range — the range and the frame are different axes. In existing-source mode, reuse the page's recorded range (named in `title:`), re-asking only to change it.
   - **Existing-source mode only — confirm the reason, then run the always-on checks** in `references/existing-mode.md`: the reingest reason (no reason given → ask, since a reingest without one creates drift), the `needs-update` / `*[tentative]*`-resolution checks, the schema-migration check against the page and its dependents, the frames decision (reuse / append / clear, with its scope-widening test), and the deep-purpose recovery. Locate every dependent — every page listing this source in `sources:` — so Step 7's cascade can reach it.

2. **Read the source in full (confirm full-text coverage).** Read the raw file from `0-raw/` (use the existing page's `file:` frontmatter to find it in existing mode). **Every ingest — new, existing, normal, or deep — fully reads the raw, cover to cover. There is no targeted partial re-read; the reason, frames, and depth control what gets written, never how much gets read. The one exception is a book, whose read unit is the Step 1 range, read in full.** Deep mode reads the whole raw — for a book, the whole chosen range — and additionally goes deeper on the equations/figures/tables the depth purpose needs; out-of-scope sections within the read unit are still read, just written only as the scope admits. A long survey or paper is still read cover to cover; when one source would make an oversized page, propose chapter-level source pages instead (each split unit still read cover to cover) — only a book is scoped by an up-front range prompt. If frames are in effect, read through them as well, keeping both the framed and a general read in mind. **Read critically as well as comprehendingly (Darwin's golden rule):** on sight, capture what cuts against the source's claims, the assumptions it leaves unstated, and the strongest sceptical critique — disconfirming evidence escapes attention unless caught as you read; when a frame is active, also ask what cuts against the frame's thesis (a positive lens must not become confirmation-seeking). These feed `Assumptions`, `Appraisal`, and concept-page `Disconfirming Evidence`, and `Contradictions` where they bear on scope. **Confirm full-text coverage before drafting** by the positive probe in `verification.md` → Full-text coverage: the final page/section of the read unit — for a book, of the chosen range, not the whole file — present and intelligible, and body text extractable (or, for an image- or media-based raw, every slide, frame, or figure present and legible). If coverage is partial (truncated, image-only, OCR-garbled, paywalled, partially extracted), surface it in the planning step and draft only what is covered — never summarize partial content as the whole source. If the source's relevance is unclear, see Edge Cases before drafting.

   **Register the raw's pagination before any locator is written (PDF raws).** What a page prints (`p. M`) is a fact about the raw, not derivable by rule — an appendix may restart numbering, a proceedings build may start high, a body may print no number — and getting it wrong yields a confidently-wrong citation that passes every structural check. Record it once per raw in `.claude/skills/multi-skill/pagination-map.md`:

   ```bash
   # in the llm-wiki conda env (fitz, pdftoppm, magick); pagination_map.py exits 3 if PyMuPDF is missing
   python3 .claude/skills/multi-skill/scripts/pagination_map.py 0-raw/papers/{stem}.pdf                        # propose a map from headers and footers
   python3 .claude/skills/multi-skill/scripts/pagination_map.py --verify 0-raw/papers/{stem}.pdf "$(mktemp -d)"  # render both margin crops to eyeball
   ```

   The generator proposes; **the user confirms** — resolve every `review(header=...,footer=...)` candidate from the rendered margins or full page yourself (never paste an unresolved value into the map), then post the whole proposed section in chat, compressing unbroken runs, and ask in one `AskUserQuestion` (approve as proposed / revise a line / other) before the `## 0-raw/papers/{stem}.pdf` section lands. A wrong `none` licenses stripping a correct printed page from every citation to that raw, and `locator_page_mismatch` validates against the very entry that would be wrong, so the schema puts a human in the loop (`CLAUDE.md` → Stay In Your Lane). This fires once per new raw, and on a reingest only when the raw is unregistered or changed. If `pagination_map.py` errors or resolves no candidates (a scan with no readable margins), say which in the Step 3 context post and the Step 8 report — "unregistered" is a deliberate outcome, never the residue of an unmentioned tool failure. An unregistered raw still ingests (the locator checks fall back to the `app.`-anchor heuristic) but raises `pagination_map_unregistered`, and `locator_page_mismatch` cannot run on it. In existing-source mode, register the raw if it is not already; a raw modified or re-committed since the map's `updated:` (`git log -1 --format=%cI` on the raw) may have re-paginated, so re-verify the entry rather than trusting it.

3. **Surface the plan via `AskUserQuestion`.** Post a single chat context message first — the full slate, so the sequence is no surprise and the user can pre-empt whole classes in chat ("just the obvious concepts, skip the images"). Then ask, batching as far as the decisions allow (`CLAUDE.md` → Workflow Rules): same-type include / drop slates go out as `multiSelect` questions, so a dense paper's candidates take one or two calls rather than fifteen, with each candidate's rationale and its `(Recommended)` marking kept in its option `description`. Contradictions, relationship-sweep edges, and anything needing free-form input are asked on their own. `references/planning-questions.md` says which decision type batches and which does not. Step 3 is complete only when every decision type with at least one candidate has been put to the user — including the easy-to-skip contradiction and relationship-sweep questions; do not advance to Step 4 with mapped-but-unasked relationships or contradictions outstanding.

   The context-post catalogue (frame echo, takeaways, sibling back-references, contradiction cross-check, relationship sweep, retrieval tags, disconfirming evidence) and the decision types (the emphasis question, then membership questions 1–10) are in `references/planning-questions.md` — work the plan through it. The relationship sweep it gates runs the role-by-role method in `.claude/skills/multi-skill/references/relationship-sweep.md`; read that file directly.
   Only approved items become wiki content. Do not act on partial answers. If the user pauses mid-sequence, wait; on resume, keep the answers already given and continue from the next unanswered decision (do not re-ask answered ones or discard them).

4. **Extract or prepare approved attachments.**

   - **Clean-tree gate — run this before anything else in this step (both modes).** Confirm a clean working tree for every *pre-existing* file this run will overwrite: the source page (existing mode), every attachment file a `replace` will overwrite, every dependent the Step 7 cascade will touch (located in Step 1), and every pre-existing concept/entity page a Step 6 edit will touch — attach-to-existing, reciprocal `Contradictions`, sibling back-reference — which occur in **new** mode too; plus, on a rename, the legacy page and its attachments folder. `git status --short` each path; if any is dirty, surface via `AskUserQuestion` (proceed / commit-or-stash first / abort) — an uncommitted prior edit is lost silently on overwrite and git history is the only preserved prior view (ingest does not snapshot to `2-outputs/`; `CLAUDE.md` Safety: never overwrite silently). Brand-new pages have no committed prior view and are not gated.

   Then write each approved image to `1-wiki/attachments/{stem}/{name}.{ext}` (create the folder if needed) — PNG by default, JPG for photographic content, SVG where the raw supplies native vector (`CLAUDE.md` → Attachments). Tools:
   - PDFs: `pdftoppm -png -r 300 -singlefile -f {page} -l {page} "{raw}" {outprefix}` renders one page to `{outprefix}.png` (300 DPI per `CLAUDE.md` → Attachments). `references/attachments.md` covers the `-singlefile` naming caveat, the `pdfimages` embedded-raster path with its indexed-name/`.ppm` rename fixups (rename to the approved `{name}.{ext}` before embedding, or the Step 5 embed dangles), the preferred PyMuPDF point-space clip, and the mandatory coordinate checks (empty-candidate, straddle, near-miss, scan-substrate) — the only guard against a half-clipped figure, which Step 8 cannot catch.
   - Non-PDF media already in `0-raw/media/`: copy into `1-wiki/attachments/{stem}/` — a copy, never a symlink, since quarantine's byte-identity check and git both need an independent file. If the copy fails (missing or unreadable file), report it and ask rather than leaving a dangling embed.
   - **Existing mode:** these mutations run only after the clean-tree gate above and any approved legacy rename (a `replace`/`remove` overwrites or moves a committed attachment). `add` writes as above — to an occupied path it is a `replace`: quarantine first, never overwrite silently. `replace` first quarantines the file it will overwrite to `2-outputs/forget/quarantine/attachments/{stem}/{name}.{ext}`, then writes. When a `replace` changes the image *content* (a corrected figure, not a tighter crop or higher DPI), treat every page embedding that path as a dependent — grep the embed path `1-wiki/attachments/{stem}/{name}` across all of `1-wiki/` (a path-qualified embed can be reused by a page under a different stem, so not only this source's `sources:` dependents) and set every `verified` page embedding that path to `status: draft`, stripping `verified_hash:` in the same edit (`CLAUDE.md` → Page Status puts an embed whose target image changes on the demote list; the body text is byte-identical, so the hash does not move and lint cannot catch a forgotten demotion — this one is ingest's to apply, and it is mandatory, not discretionary). `remove` quarantines to the same path (Limits). Both quarantine paths follow `.claude/skills/multi-skill/references/quarantine-path-convention.md` (the `cmp -s` byte-identity check, the `git check-ignore -q` guard, and the `-N` name-clash suffix rule).
   - If extraction fails (encrypted PDF, vector-only figure, or a crop that cannot be contained without swallowing body text — `references/attachments.md`), report it instead of silently skipping, and put the fallback to the user as a fresh `AskUserQuestion` (the Step 3 approval assumed a clean extraction that did not materialize): drop the embed, accept a locator-only reference, try a different render, or place a manual screenshot. A dropped embed must also be removed from the Step 5 write plan and never written to `attachments:` or embedded in the body, or Step 8 catches it as a dangling embed.

5. **Write or update the source page** at `1-wiki/sources/{stem}.md`. Use the source-page frontmatter and required callouts from `CLAUDE.md`. Every callout carries a block ID — the kebab-case of its display title — as the last line inside the `>` block (`> ^tldr`, `> ^evidence`, …; no blank `>` line before it; `CLAUDE.md` → Callout Block IDs), on every callout including empty placeholders and any inserted by the schema-migration check. For PDF raws, every non-obvious claim carries its location in whatever callout it sits in — the own-voice `Appraisal`/`Assumptions`/`Open Questions` are the exemption (`CLAUDE.md` → Source Pages) — as a `#page=N` deep-link with the structural anchor and page **together inside** the display: `[[0-raw/papers/{stem}.pdf#page=5|sec. 3, p. 5]]` (never split the anchor outside the link or leave a page-only display — lint `source_locator_incomplete`). Cite abstract-drawn content `abstract, p. 1`, never relabelled `sec. 1`. Non-PDF raws use the per-type locator formats (`CLAUDE.md` → Source Pages → Evidence pointer formats), written in a backticked span rather than a wikilink to the raw. `N` is the physical PDF page, which differs from the printed page whenever pagination does not start at 1 — read `p. M` off the pagination map registered in Step 2 (not by re-deriving an offset a restarting appendix would defeat), and where the map says a page prints nothing, drop `p. M` and cite the anchor alone (`CLAUDE.md` → Source Support And Verification; `lint`'s `locator_page_mismatch` checks every `p. M`). Worked examples and the figure-crop loop are in `references/attachments.md`.
   - **New:** draft the full page with `status: draft` (a later `audit` promotes it). `file:` points at the raw path-qualified into `0-raw/` (`file: "[[0-raw/papers/<bibkey>.pdf]]"`); authors use pipe-rendered display, auto-linking any author already in `1-wiki/entities/` and leaving a one-off collaborator with no page as a dangling path-qualified `authors:` wikilink (a new author page is proposed only via a Step 3 create-new question, and only for a prominent author — `CLAUDE.md` → Author page creation policy).
   - **Existing:** if Step 3 approved a legacy-page rename, run the rename block in Step 4 before any attachment write — working tree confirmed clean — `git mv` the legacy page `1-wiki/sources/{legacy}.md` → `1-wiki/sources/{stem}.md` and its attachments folder `1-wiki/attachments/{legacy}/` → `1-wiki/attachments/{stem}/` — the folder move only after confirming `1-wiki/attachments/{stem}/` does not already exist, since `git mv` into an existing directory nests (`{stem}/{legacy}/`) instead of renaming, dangling every embed the rename then rewrites; on a collision, surface it via `AskUserQuestion`. Then rewrite every inbound reference per `.claude/skills/multi-skill/references/inbound-reference-discovery.md`, before any write — otherwise the write lands a fresh `{stem}.md` beside the untouched legacy page, re-creating the duplicate the Step 1 guard exists to prevent. On each `verified` page whose inbound link this rewrites as a same-target, display-unchanged repair, that is an allowlisted stale-path repair: recompute and rewrite its `verified_hash:` with `body_hash.py` in the same pass, so one rename does not demote every page that linked to the renamed one. That reference's carve-outs (a retargeted link, a transplanted `#page=N` deep-link) are never self-re-stamped — follow its demote / mark rule instead. Then preserve `type:`, `file:`, and `created:`; touch `updated:`. Apply the Step 1 schema-migration check — insert each missing required callout in its correct position from `CLAUDE.md`, filling from the raw where the scope makes that natural, otherwise the empty placeholder. Sync `attachments:` with the current files (drop entries for quarantined files). Keep `Concepts and Entities` synchronized. Fold any stale Figures callout's embeds into `Evidence`/`Method` and drop it.
   - **Frames frontmatter:** record each frame as an item in the `frames:` list; in existing mode apply the Step 1 frames decision. `frames:` is always present — write `frames: []` when unscoped, never omit it — and appears in frontmatter only, never in the page body.
   - **Re-voice every bullet; never copy the source's sentences.** Write each bullet from the idea you carried away, changing sentence structure and clause order — swapping synonyms into the source's sentence leaves it lifted. Verbatim wording is allowed **only** inside quote marks paired with a locator, for the load-bearing `Evidence` anchor a Key Claim needs. Self-check: a bullet a reader could find by searching the raw is not yet re-voiced. Details in `references/source-page-writing.md`.
   - Per-callout writing guidance (what genuinely belongs in each of `TL;DR`, `Contribution`, `Key Claims`, `Evidence`, `Method`, `Assumptions`, `Limitations`, `Appraisal`, `Concepts and Entities`, `Contradictions`, `Open Questions`, `Connections`), the inline-embed format, and the citation / `attachments:` / no-bold rules are in `references/source-page-writing.md`.

6. **Draft or update concept/entity (and synthesis) page changes** (drafted here; Step 7 writes them, so a Step 6 abort leaves no half-written page).
   - For each approved concept/entity page, apply the one-idea test: one idea or named thing? explained simply? reusable for later writing? reads standalone with its source page closed? supported by at least one source page? connects to existing notes?
   - Existing page: a small edit (usually 1–3 bullets or a tighter `Idea`). New page: the full concept/entity template from `CLAUDE.md`, written `status: draft` with `aliases:` populated when the source gives the concept a genuine acronym, alternate name, or older term (e.g. `aliases: [Adam]` on an Adaptive Moment Estimation page — `CLAUDE.md` → Concepts and Entities) and on a same-as merge, otherwise `aliases: []`, each callout ending in its block ID — the kebab-case of its display title, so `[!why]` Why It Matters takes `> ^why-it-matters` and `[!disconfirming]` Disconfirming Evidence takes `> ^disconfirming-evidence` (see `CLAUDE.md` → Callout Block IDs). Only fill sections with genuine content — a new page often earns only `Idea`, `Why It Matters`, `Sources`; the rest stay `> - None yet`.
   - At most one defining image per page, embedded in `Idea`, illustrating the idea (not summarizing the source); never in `Examples`. Deep mode: do not push equations, metric tables, or long method detail into concept/entity pages unless the page is explicitly about that idea.
   - Add the source to `sources:` (`- "[[1-wiki/sources/{stem}.md|{stem}]]"`) and the `Sources` callout. Cite each non-obvious factual claim inline to the specific source it draws from, in one of the two canonical forms — `CLAUDE.md` → Source Support And Verification is the authority for both, and a bare source link with no located deep-link is incomplete on a non-obvious claim; leave obvious/definitional bullets and own-voice judgement (`Open Questions`, and a `Disconfirming Evidence` bullet only when it is a purely own observation with no source) uncited — cite sourced counterevidence like any non-obvious claim — not citation wallpaper. Never fabricate a locator: if you cannot confirm the page or section in the raw, mark the claim `*[unverified]*` / `*[tentative]*` or quote-and-locate only what you can confirm — a plausible but wrong `#page=N` is worse than an honest gap. On a bullet naming two or more sources (the cross-source callouts — `Contradictions`, `Not This`, `Disconfirming Evidence`, synthesis `Tensions`), cite each clause to the source that states it, not the source the bullet is framed about (`CLAUDE.md` → the multi-source-bullet rule). Word each cited claim to represent its source faithfully — no overstatement (Step 8 re-checks claim by claim); a causal/comparative/evaluative claim carries its source's reason, never a fabricated mechanism (recast as own-voice or flag `*[tentative]*` if the source gives none). Wikilink every genuine reference to an existing wiki page, on every occurrence; a page never links to itself. Name the source, never a vague referent ("the paper", "the study", "the authors") — lint's `vague_source_referent`, not auto-fixable. See `CLAUDE.md` → Source Support And Verification, Plain-Language Style, and Wikilink Format.
   - Synthesis pages (existing mode): keep the cross-source answer, evidence map, tensions, and source list; update embeds the same way. ingest only updates an existing synthesis whose source list this source already belongs to; it never creates a synthesis page — that is `synthesis`'s job. A source that strengthens a new multi-source cluster is surfaced as a synthesis candidate in Step 3, not authored here.

7. **Apply approved edits; cascade (existing mode).** Mechanical fields need no separate approval: `created:` (new pages), `updated:` (touched pages), `source_count:` to the distinct works behind `sources:` (from `source_count_mismatch`), `attachments:` to match files, `Concepts and Entities` callout updates, and `1-wiki/index.md` entries for new/renamed pages.
   - **Existing mode — cascade `needs-update`.** Walk every dependent (located in Step 1) and apply the shared dependent-cascade mechanics in `.claude/skills/multi-skill/references/dependent-cascade.md` — what a dependent is, the `needs_update_reason:` hand-off and append-don't-overwrite rule, `source_count`/`Sources` sync, the `verified_hash` strip on demotion, and the zero/single-source guards. In ingest, **material** means a deeper read corrects a claim the dependent built on, adds a contradiction it doesn't track, or revises an interpretation it inherited — set the dependent `status: needs-update` with the hand-off reason (e.g. `needs_update_reason: inherited the pre-correction claim from {stem}; reingest revised it — re-check the Key Claims figure against {stem} Evidence and update or drop`); **additive-only** (extra evidence, fixed typos, still-correct fuller write-up, attachment adds) does not cascade — touch `updated:` only on dependents whose `Sources` callout changed mechanically. When the cascade adds or changes a claim on a `verified` dependent, apply the status/marker rules from Conventions (Recap).
   - **Existing mode — schema-migration to dependents.** For each dependent flagged in Step 1 as missing callouts, insert them in correct position as empty placeholders (`> - None yet`); do not fill from the source page unless the scope naturally produces the content. Remove obsolete line-by-line citation style when encountered. Update `sources:` and `source_count`. Preserve contradictions.

8. **Run ingest verification.** Run the two independent verification packets in `.claude/skills/multi-skill/references/verification.md` over the raw source and every page created or touched — independent meaning each re-derives its checks from the raw, not the drafted page (the tiered independent-refuter model, run here at the authoring tier that reference defines — the packets plus one refuter — an independent subagent given the claim and the raw and told to refute it — per owed unit in its three classes: each aggregate or generalization claim, each restated number, and each cited clause of a cross-source bullet; never a pair, never at page granularity; the Tier-2 pair that earns `verified` runs later at `audit`). **One refuter call may carry a batch of same-raw owed units and return a per-unit verdict — roughly 25 units per call at most, never pooled into a page-level verdict — so owed units and refuter calls are not the same quantity.** Record, per packet, the one late-section raw detail re-located, one detail from roughly the middle of the read unit (an endpoint-only probe is satisfied by seeking to the last page), and the one `#page=N` spot-checked (or `n/a` for a non-PDF) — a packet recording neither has not re-read the raw and the ingest is not complete — and open every locator on a cross-source bullet (no sampling, since a mis-located citation hides behind a good sibling). Record once for the run the authoring-tier refuter spend — owed units authored versus refuter calls made (the report line in `verification.md`); calls should be far fewer than units once batched, and more *verdicts* than owed units means the run escalated past the authoring tier. Any mid-run citation fix triggers the repeated-literal sweep across `1-wiki/`; record it. Also run `python3 .claude/skills/multi-skill/scripts/check_wiki.py "1-wiki"`, filtering its JSON to the pages this run wrote by parsing the array rather than line-grepping (a clean wiki prints `[]`, so empty or unparseable stdout is a failed run, not zero findings), and clear every error-severity finding on those pages except `status_needs_update` (Step 7's cascade sets it) before the packets count clean. Apply and re-run on any fix; the operation is complete only when both packets are clean in the same round, bounded to three fix-and-rerun rounds (stop and report on non-convergence or an oscillation, rather than looping — a stopped run is not aborted: leave the pages as last written, record the unresolved findings in the report, and still run the remaining steps). The reference routes the report — both modes write `2-outputs/ingest/ingest-YYYY-MM-DD-HHMM-{stem}.md` (take the one `TZ='UTC' date '+%Y-%m-%d-%H%M'` stamp here; later steps reuse it) and record frames/purpose; the two body templates are in `references/report-shapes.md`. Close the report with its `Recommended next ingests` section per that file, then the `## Self-report` block (`.claude/skills/multi-skill/references/self-report.md`), surfaced again in the chat close. Do not set any touched page `status: verified` — verification is a safety pass; pages stay `draft` until a later `audit`. Apply the Conventions (Recap) status/marker rules to any `verified` page this run edits, in either mode. Because lint is structural, it will not catch a `frames:` widening that fails to grow the body — this packet is that guard.

9. **Update `1-wiki/hot.md`.** Reuse the Step 8 stamp in this bullet and the log heading (one stamp, not re-fetched per step, never a bare `date` — a re-fetch drifts them across a minute boundary).
   - Prepend Recent activity: `- [YYYY-MM-DD HH:MM] {ingest | ingest-deep | reingest} | {stem}` (verb by mode).
   - Add new low-coverage, `needs-update`, and contradiction-bearing concept/entity or synthesis pages to Open threads (pipe-rendered wikilinks).
   - Never edit Active focus unless explicitly asked.

## Edge Cases

- **Ambiguous or missing filename.** If the user names a source without its exact raw filename (e.g. "ingest the attention paper"), resolve the `{stem}` from `0-raw/` and confirm it before reading. The resolved stem also determines new vs. existing mode (Step 1).
- **No matching raw, or a path outside `0-raw/`.** If nothing under `0-raw/` resolves, stop and report the candidates considered — never create a source page for a raw that is not there. If the named source sits outside `0-raw/` (a path elsewhere on disk, a chat attachment), stop and ask the user to place it under the right `0-raw/` subfolder with the stem they want; ingest never writes to `0-raw/`. Resume once it is there.
- **No durable idea (new).** Create only the source page; do not invent concept/entity pages.
- **Near-duplicate concept/entity page.** Update the existing note instead of creating a new one.
- **Contradiction.** Preserve both sides in `Contradictions`; set affected concept/entity or synthesis pages to `needs-update`.
- **Source relevance is unclear.** Use `AskUserQuestion` to ask whether to ingest, skip, or file only a minimal source page.
- **No frame provided.** Default to unscoped: generate your own takeaways and contribution; no missed/adjacent buckets surface.
- **Frame provided but the paper doesn't fit it.** Say so in Step 3 before any questions, via one `AskUserQuestion` with three options: (a) widen the frame, (b) drop the frame and ingest unscoped, (c) skip the source.
- **Deep ingest without a purpose.** Ask before reading; fall back to normal mode if the user can't articulate one.
- **Existing mode — reingest reveals a new reusable idea.** Propose it; do not create it without approval.
- **Existing mode — a reingest landed wrong and needs reverting.** The prior committed page view is in git (ingest does not snapshot to `2-outputs/`): restore it with `git checkout <sha> -- 1-wiki/sources/{stem}.md`, then reverse this run's cascade — walk the Step 7 dependents and strip only the `needs_update_reason:` clause this run appended, preserving any prior hand-off (`dependent-cascade.md` append rule). Also restore any attachment this run quarantined (from `2-outputs/forget/quarantine/attachments/{stem}/`), and remove the pages plus the `index.md`/`hot.md`/`log.md` entries this run added — or `forget` them, since `git checkout <sha>` cannot delete files that did not exist at `<sha>`. A new-mode ingest that landed wrong is reversed by `forget` on the source page and every concept/entity page it created. Uncommitted prior edits are not recoverable, which is why Step 4 gates on a clean working tree.
- **Existing mode — reingest weakens support for a dependent.** Mark it `needs-update` or remove the source from its support list after approval. If the dependent is a synthesis and removing this source drops it below two sources, do not leave it lint-failing: surface the shared stub-or-remove decision via `AskUserQuestion` — set `single_source_stub: true` (deliberate stub), re-source it, or quarantine it (`forget`) — and write a precise `needs_update_reason:` if it stays under-supported.
- **Existing mode — saved frames no longer fit the reason** (e.g. a contradiction outside every frame). Surface it in Step 3, and take the frames decision from `references/existing-mode.md` → Frames Check.
- **Existing mode — existing attachment is fine.** Default `keep`: no extraction, no embed change.
- **Concept/entity page would exceed one idea, or evidence is too dense.** Split the page; keep dense evidence in the source page (split by section if needed).
- **Image extraction fails.** Report it in Step 4; offer a locator-only reference, a different render, or a manual screenshot the user places in `1-wiki/attachments/{stem}/`.
- **The user only needs a few missing details on an existing page.** That is existing-source mode with reason `missed evidence` — a full re-read with a targeted write, not a full deep pass.

## Limits

- One source per invocation.
- Never modify `0-raw/`. Image extraction writes only to `1-wiki/attachments/{stem}/`; removed attachments go to `2-outputs/forget/quarantine/attachments/{stem}/` (never deleted outright).
- Concept/entity pages stay atomic and short; deep detail belongs in source pages unless it is itself the reusable idea (the one-defining-image cap is Step 6's, not restated here).
- Frames and the depth purpose scope the source page only, never the concept/entity pages (which stay reusable across future framings). The remaining cross-cutting rules are stated once upstream, not re-argued here: deep requires a stated purpose (Depth), sections are not quotas (Purpose), no bold or italic and pipe-rendered `.md` wikilinks (Conventions).
