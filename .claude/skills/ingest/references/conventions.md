# ingest — Conventions (Recap)

The shared `CLAUDE.md` rules `ingest` leans on, recapped in one place. Read this at Step 1 with the memory files, before the first decision or write: Step 3 applies the `AskUserQuestion` rule, Steps 4–7 the filename and wikilink forms, and Steps 7 and 8 the status and marker rules. `CLAUDE.md` stays authoritative wherever this recap is thinner than the schema.

- **Source-page filename matches the raw source stem exactly** (drop the extension, preserve case and internal punctuation): `0-raw/papers/<bibkey>.pdf` → `1-wiki/sources/<bibkey>.md`; `0-raw/articles/<slug>.md` → `1-wiki/sources/<slug>.md`. The attachments folder uses the same stem: `1-wiki/attachments/{stem}/`.
- **Every wikilink is path-qualified from the repo root, includes `.md`, and uses a pipe-rendered display name** that reads naturally: `[[1-wiki/concepts/scaled-dot-product-attention.md|Scaled Dot-Product Attention]]`, authors `[[1-wiki/entities/ashish-vaswani.md|Ashish Vaswani]]`. The pipe display is required (a bare path renders unreadably) and carries no whitespace around the pipe (`[[path|display]]`, never `[[path | display]]`); attachment embeds `![[...]]` take the path but no pipe.
- **No bold and no italic in wiki content** (source, concept/entity, synthesis, hot/index/log). The only structural exceptions are LaTeX math and the bullet markers `*\[unverified\]*` / `*\[tentative\]*` / `*\[disputed — see Contradictions\]*`. Inline backticks for paths, code, and quoted prompt addenda are fine.
- **Use `AskUserQuestion` for every user-facing decision** in Step 3, batching as far as the decisions allow (`CLAUDE.md` → Workflow Rules): same-type include / drop slates go out as `multiSelect` questions (up to four options each, four questions per call) with the per-candidate rationale in each option's `description`; contradictions, relationship-sweep edges, free-form input, and any decision whose answer changes the next question are asked on their own. Mark the option you recommend `(Recommended)` and place it first — base the lean on your read of the source (e.g. `Include (Recommended)` for a clearly-warranted concept page, `Drop (Recommended)` for a marginal candidate). Omit a recommendation only on a genuine no-lean call, and say so in the question. Phrase every question and option label for a reader who knows nothing about the wiki's internal vocabulary — gloss any callout, status, or frames term inside the option (present `add to Not This` as "record as a contrast (Not This)", `mark needs-update` as "flag for re-checking (needs-update)", `clear to unscoped` as "widen back to the whole source"), the same way the Step 1 depth question already describes both modes plainly.
- **Structural authority lives in `CLAUDE.md`.** Required-section lists, frontmatter blocks, block-ID placement, and locator rules are the shared schema — this skill cites `CLAUDE.md` rather than copying (copying drifts). The Step 8 verification spec lives in the shared `.claude/skills/multi-skill/references/verification.md` (one canonical copy, since `query` runs the same packets). The extraction/citation *procedures* the agent runs are self-contained in the skill's steps and `references/`.
- **Status and markers (recap).** New or changed durable content stays `status: draft` (a later `audit` earns `verified`); ingest never sets `verified`, and re-stamps `verified_hash:` only for the verification-neutral edits `.claude/skills/multi-skill/references/verification-neutral-fixes.md` assigns it (a stale-path repair in its rename cascade; a content-identical claim relocation) — recompute with `body_hash.py` in the same pass, no raw re-read. On a `verified` page this skill edits, in either mode: a **new** non-obvious claim added but not raw-fact-checked this pass is marked `*[unverified]*`, and the page keeps `verified` with that claim as its pending delta (a masked new line never enters `verified_hash`); a **changed** verified claim moves the hash and demotes the page to `draft` (marking does not hold it) — strip the now-stale `verified_hash:` in the same edit — as do an embed or `Sources` change and a `frames:` scope-widening (which grows the unmarked body). Mechanical frontmatter touches (`updated:`, `source_count:`) are hash-safe. Full rules: `CLAUDE.md` → Page Status and Bullet Markers.
