# audit — Apply The Fixes (Step 7)

The fix mechanics for `audit` Steps 4a and 7. SKILL.md is the overview; this file is the detail it directs you to read before editing any page. The scope model, the relationship-integrity barrier, the terminal-verification invariant, and the marker/hash mechanics these fixes rely on are defined once in SKILL.md → Verification Model — read that first.

Step 4a completes the verification-neutral/no-raw lane before `READY(n)`; Step 4b applies determinate target repairs; Step 7 applies every residual content edit. Step 7's results are re-verified and stamped in Step 8 (`references/verify-and-set-status.md`). Verification is terminal for content-changing work, so no content fix follows that stamp. Act without asking the user — audit is the autonomy exception, and `CLAUDE.md` grants that autonomy only after a fact-check against the raw. The exception does not weaken that condition: positively establish a stale path from canonical page identity, and settle any support, provenance, citation-target, or relationship change against the authoritative raw/source evidence before applying it. An indeterminate target is not edited; record its exact identity and finalize `incomplete` if it cannot be settled autonomously.

## Confirm The Defect Before Fixing It

A suspicion is not a finding. This guard governs every fix below, and it exists because audit's errors are asymmetric. A missed defect stays on the page, visible, for the next run to catch. An invented defect does the opposite: audit overwrites correct content, re-stamps the page `verified`, and every later `partial` run trusts it — the error is now certified and self-concealing. A false-positive fix is strictly worse than the defect it imagines. So the burden of proof runs one way: before changing existing content, establish the defect positively against the raw — never from a pattern, a plausible inference, or a prior report's say-so.

Four per-instance guards:

- **Per-instance, never per-pattern.** "This class of anchor is usually off by one" is a hypothesis, not evidence. Confirm the specific locator, claim, or bullet is wrong by opening the raw at that place. Sections and tables straddle two physical pages, so a locator naming either page can be correct; a table floats away from the subsection that discusses it; a section that "should" be 3.3 may genuinely also sit on 3.2's page. Each reads as an off-by-one to a pattern-matcher and is not one.
- **Never inherit a finding from a prior report.** Re-derive it, or drop it. A finding copied forward carries the earlier run's errors with laundered authority — a wrong "correction" recorded as a correction is the hardest kind to see, because it arrives pre-justified. Re-check any figure, count, or defect a previous audit claims to have fixed; that is where a `full` pass earns its cost.
- **A carve-out is confirmed against every instance before any bulk application.** A rule that holds for one source (an appendix with no printed pages) may be false for the next (one that restarts at 1, or continues the body's numbering). Applying it on faith to the whole corpus destroys the correct instances. Check each source; expect the corpus to split more ways than you assumed.
- **When a check's own tooling supplies the evidence, test the tooling first.** A regex or script that "finds" a defect is a hypothesis until you have shown it does not also match correct content. Run it against a known-good case before believing a known-bad one.

A defect you cannot confirm is not fixed. Record the exact uncertainty; if it blocks a content obligation, set the page `needs-update` with a precise reason, strip its hash, and remove any process marker rather than masking the uncertainty. Before treating any marker as process state, apply SKILL.md's canonical-marker preflight: migrate a real suffix/noncanonical marker to the `> - *[unverified]* …` prefix position, keep inline/fenced-code and HTML-comment literals byte-identical, and route an unresolved literal/process distinction to exact pending work. When the fix is structural, state the load-bearing inference as a yes/no audit assumption (`references/verification-spec.md`).

**The mis-located-citation exception.** A citation-location defect can become self-concealing under a stamp. Open the exact cited page — never confirm from document-wide search, where a repeated name may occur elsewhere. If the cited page supports the claim, it is verifiable. If it cannot be confirmed this run, do not pass it on plausibility or carry a marker: set the page `needs-update` with the exact locator uncertainty and strip its hash. Both branches preserve the per-instance proof burden.

## Verification-Neutral Worklist Transactions (Step 4a)

Before final `READY(n)`, lint's authored worklist often names verification-neutral fixes on a `verified` page that carries no `*[unverified]*` markers. In `partial`, that page needs no Step 5 fact-check when this is its only work; in `full`, the ordinary whole-wiki verification scope still applies. The four categories `CLAUDE.md` → Page Status assigns to audit:

- an unlinked genuine reference to an existing page (`unlinked_page_mention`);
- an open compound to de-hyphenate (`hyphenated_open_compound`, or slug-derived bidirectional `hyphenated_open_compound_noun`; confirm the noun-vs-modifier call from page context; an ambiguous candidate is not a neutral edit and remains exact pending work rather than receiving a marker);
- a US spelling to normalize;
- an incidental reciprocity-callout link to unwrap (the `missing_reciprocal_contradiction` over-count; see the dispositions below).

(The four format fixes — `callout_block_id`, `wikilink_pipe_spacing`, `citation_bracket_style`, `embed_not_isolated` — are lint's to apply and re-stamp, not audit's.)

These edits are on the verification-neutral allowlist (`CLAUDE.md` → Page Status; `.claude/skills/multi-skill/references/verification-neutral-fixes.md`). Capture the immutable Warning baseline before edits, group the complete plan by page, freeze every exact transform against one page preimage, reject overlaps, and apply descending byte offsets as one operational page transaction. Emit the exact `neutral_page_transactions` reconciliation row defined in the shared reference only when the page transaction contains one or more frozen `genuine_wrap` occurrences; that executable schema deliberately does not attest de-hyphenation, spelling, or incidental unwrapping. For a `verified` page, run `body_hash.py` once before editing, require equality with `verified_hash:`, then touch `updated:` once, hash once, and write the new hash once. For another status, touch `updated:` once, preserve status, write no hash, and retain ordinary fact-check scope. A verified page changed only by one of the three non-wrap neutral categories also preserves `status: verified`, but stays in ordinary partial fact-check scope rather than claiming the genuine-wrap raw-proof bridge. The Step 4a edit transaction performs zero raw reads, bullet/page readers, markers, or demotions. A mismatched verified preimage enters ordinary scope. A stale span aborts the page plan and requires a fresh census; never substitute a nearby occurrence.

The guard is the allowlist's tightness: wrap an existing plain-text reference only where the rendered display stays byte-identical and the target page exists (never change which page a link targets, or a claim's wording); de-hyphenate only from a published open-compound mapping (the always-open mapping everywhere, the noun-only mapping in bare-noun position) and normalize spelling only in running prose — never inside a verbatim quote (`"…"`), an inline `` `code` `` span, a math span, a title, or a dataset/model identifier, where rewriting the token would change what the page asserts the source wrote. A hyphenated compound or US spelling inside one of those is not claim-neutral: leave it, and if it is the only worklist item, leave the page untouched.

Every non-neutral item — content rewrite, split/merge, citation-target or locator change, claim correction, or cross-page edit — enters current fact-check scope. Two safe paths exist. **Delta-certify** a bounded fix on a hash-stable page: verify the pre-edit hash, apply the fix, rebuild the exact changed/new/revoked claims and every declared or conservative dependent, run both bullet roles for those claims, retain only exact-valid unaffected rows, run both fresh whole-page roles on the complete final page/raw manifest, then re-stamp. **Complete-page certify** an unbounded change by rebuilding all claim evidence and both page roles. A new/relabelled locator anchor or any change that cannot be certified this run ends `needs-update` with a precise reason, no hash, and no process marker. Masking and later-audit deferral are not dispositions. When boundedness is doubtful, use complete-page scope; when certification is unavailable, use `needs-update`.

## Grow The Check Data Lists

Two lint checks are heuristic and carry curated lists audit maintains, in two agent-writable data files under `.claude/skills/multi-skill/`. Both are data, not script (editing them is not the "audit does not edit scripts" case), and both are loaded as runtime data, so an entry changes a check's behaviour, not its code.

- `hyphenation-lists.md` drives the bidirectional `hyphenated_open_compound_noun` check with four lists (DISALLOWED open-noun compounds, ALLOWED keep-hyphenated look-alikes, direction-2 HEAD nouns, VERIFIED-IGNORE phrases). Audit maintains all four, learning from what it sees: a confirmed slug-derived open compound → DISALLOWED; a hyphenated proper name or established term a flag would wrongly open → ALLOWED; a genuine head noun → HEADS; a flagged-but-correct use → VERIFIED-IGNORE.
- `unlinked-mention-ignore.md` is the verified-ignore list for `unlinked_page_mention`. An occurrence audit confirms is generic wording — a homograph, a common noun that happens to be a page title, the term inside a larger established phrase — is appended as one `{page path} :: {target stem} :: {phrase}` line under `## verified-ignore`. Entries are page-scoped and phrase-anchored, so an entry never suppresses the same wording on another page, and rewording the sentence re-flags the mention.

For `unlinked_page_mention`, follow `references/unlinked-mention-occurrences.md`. Scanner rows are candidate groups, not occurrence identities or backlog size; every exact span receives its own terminal disposition and standing ignores take precedence before new classification.

**No addition is written on audit's lone judgement.** Before appending any entry, use two independent readers to verify it — each asked to confirm or refute the addition on its own: that a DISALLOWED compound is genuinely open as a noun and hyphenated as a modifier (not a proper name); that an ALLOWED term is a fixed hyphenation; that a HEAD noun is genuinely a noun; that a hyphenation VERIFIED-IGNORE phrase reads correctly as written; or that an ordinary unlinked-mention occurrence is generic wording rather than a reference to that page. A graph-sensitive incidental non-party uses the distinct graph-ignore HOLD question in `references/unlinked-mention-occurrences.md`; do not ask genuine-but-incidental wording to satisfy the generic-word test. Give both readers the same consecutive maximal batch — 25 exact candidates except the final smaller batch — and read access to each host page, target page, and canonical rule; do not provide a coordinator conclusion. Add an entry only when **both readers HOLD that exact candidate under its applicable question** — unanimity of two, never a majority of three. The quorum is a precondition on the write. For unlinked mentions, follow the non-HOLD routing and post-wrap revalidation in `references/unlinked-mention-occurrences.md`; for other list types, a split/refutation adds nothing and never buys a third vote. An unavailable or unparseable required reader makes the audit `incomplete` with the exact pending candidate identities. Apply accepted appends centrally in Step 4a or Step 4b as applicable, then rerun the responsible scanner. Never touch `check_wiki.py` or its test suite. If a DISALLOWED/ALLOWED/HEAD addition warrants a paired regression case in `.claude/skills/multi-skill/scripts/tests/test_check_wiki.py`, record it as a proposal rather than writing it (a verified-ignore entry needs none).

## Resolve `*[unverified]*` Markers

When audit fact-checks a claim marked `*[unverified]*`, clearing it requires the same terminal evidence as first certification: an exact-valid locator/entailment bullet pair for the unmarked generation, two fresh whole-page HOLDs on the final page, current final epoch, terminal reconciliation, and the mechanical marker/status/hash write guard. A same-agent re-read or page verdict alone never clears it.

- If the terminal evidence holds and the claim's `#page=N` anchor is already at Git HEAD, remove the process marker (leave a co-occurring `*[tentative]*`, which is a separate epistemic judgement). If its anchor is new versus HEAD, set `needs-update` with the exact anchor reason, strip the hash, and remove the process marker.
- If it fails or the refuters split, fix inline when the raw settles it; otherwise set `needs-update`, strip the hash, and remove the process marker.

The `verified_hash:` re-stamp that seals a cleared marker is a Step 8 write (`references/verify-and-set-status.md`); clearing the marker text is the Step 7 edit. A terminal `complete` or `unconverged` report has no process markers: the page either earns clean `verified`, or ends `needs-update` with its reason and no hash.

## Build The Fix List And Resolve The Authored Worklist

A page's complete Worklist ledger is the union of audit's own Step 4 findings for it and the lint authored-tier findings carried in from Step 1 — resolve every item, not only the ones audit's pass independently surfaced. The executable Step 7 fix list is the post-barrier residual: keep Step 4b's repaired items in the ledger under their durable final disposition, but mark them consumed and remove them from this queue so no repair is applied twice.

If any remaining fix changes a target, support/provenance link, page inventory or name, or relationship, apply the determinate edit under its existing disposition and invalidate the current verification epoch. Before any certification or stamp, return to Step 4b, rerun consistency, the complete lint including its LLM walk, and the relationship sweep, require zero unresolved required targets, recompute scope, and restart verification cold. A late graph edit never rides through on the earlier epoch's refuter results.

**Authored worklist items are resolved this run — deferral is not a disposition.** Every authored-tier finding lint carried in is resolved now, not logged as a focused follow-up. Run length, token economy, and the fact that a prior run deferred the same backlog are not grounds to defer — a standing authored backlog is skipped work. Batch size is not a deferral ground either: a large run (100+ `unlinked_page_mention` flags) is resolved this run. The genuine-vs-generic triage is the careful judgement; once made, applying it is not rushing. Apply every wrap the triage marks genuine. For suppression candidates, use the exact identity, consecutive maximal 25-row batches, same-digest paired-reader protocol, and post-wrap revalidation in `references/unlinked-mention-occurrences.md`.

No authored Warning cost stages across follow-up audits. Run length, batch count, token economy, or spend does not change the completion contract. If an external execution limit makes a required reader, scanner, or verification impossible after safe retries, finalize `incomplete` and enumerate the exact pending occurrence, claim, page, role, and scanner identities. A page never keeps or earns `verified` while a content-changing worklist item on it is unapplied or its final ledger/page gate is unfinished.

"Resolve" differs by check, but every disposition is reached this run:

- `missing_reciprocal_contradiction` and `concept_source_asymmetry` clear this run, but which way depends on whether the named page is a genuine party. A genuine mutual relationship gets the reciprocal entry or missing support link. On a `verified` page a support sync is an unmarked page-level assertion a claim marker cannot carry, so pull the gaining page into Step 5 and complete its new bullet ledger plus fresh page pair; if an external limit prevents completion, leave it non-verified and finalize `incomplete` with the exact pending verification identities. An incidental non-party link is unwrapped instead and recorded through the ignore-list quorum; never author a false reciprocal. If party status remains indeterminate, Audit's rule overrides the root's uncertain-reciprocal sentence: make no body/relationship edit, set the affected page `needs-update`, retain the exact obligation pending, finalize `incomplete`, and record the root-alignment item as an outside-scope `[cross-file]` proposal rather than asking or editing `CLAUDE.md`.
- `unlinked_page_mention` follows `references/unlinked-mention-occurrences.md`: wrap every exact occurrence classified as a genuine reference, and add a page-scoped phrase suppression only when both independent readers HOLD the exact candidate. Leaving an occurrence without either terminal disposition is pending work, not a false positive that can be carried forward.
- `vague_source_referent` and `source_context_leak` use `.claude/skills/multi-skill/references/verification.md` → Named source attribution. A substitution that names the one already-cited source still changes content and enters scope; a re-voicing or added citation does too. Delta-certify a bounded edit, complete-page certify an unbounded edit, or end `needs-update` without a marker when it cannot be certified. A new anchor always takes the last branch.
- `stale_mention_ignore` is determinate: a verified-ignore entry that suppresses nothing is dead, and lint has proven it. Delete the entry from `unlinked-mention-ignore.md` — no sub-agent verification, since removing an inert entry asserts nothing. The one judgement: if the occurrence still exists but was reworded, re-record it against the current phrase (re-confirming it reads as generic) instead of editing the old phrase to match.
- `intra_page_redundancy` resolves when the content settles which bullet merges or drops; a genuine coin-flip falls to the ambiguity clause. On a `verified` page the merge-or-drop is a real content change, so it fixes-and-demotes: confirm the dropped point survives (re-voiced) in the bullet that stays (the merge-content-conservation check), then drop or merge, strip `verified_hash:`, touch `updated:`, set `draft`; or, when the page is already in Step 5 scope, re-earn `verified` in the same pass. A genuine redundancy on a `verified` page is never deferred as a standing Warning to protect the stamp.

No finding is handed back as a question. A genuinely ambiguous structural call the fact-check cannot settle preserves the body, sets the page `needs-update` with the exact unresolved choice, and remains an exact pending obligation if the final scanner still emits it.

## Reciprocal Mirrors Enter Current Scope

This is the genuine-party branch; an incidental mention is unwrapped instead. A reciprocal bullet is a content change and enters current scope. Because its new anchor cannot pass the anchor-at-HEAD gate in the same run, author the determinate repair, set the partner `needs-update` with the exact new-anchor reason, strip its hash, and carry no marker. A `sources:` / `Sources` or `concepts-entities` sync likewise enters scope and either certifies or ends `needs-update`.

## Apply The Fixes

**Determinate fixes** — a finding the raw source or the schema settles outright: a restated number that does not match the raw, a misquoted phrase, a banned-vocabulary word or source-context phrase lint detected and left for audit, a non-obvious claim missing its inline citation or located locator where the fact-check identifies the supporting source and location (write it in one of the two canonical forms, `CLAUDE.md` → Source Support And Verification, with the structural anchor and printed page inside the `#page=N` deep-link and N computed from the printed→physical offset), a claim whose wording overstates or misinterprets the source, a genuine reference to an existing page left unlinked, the source's actual stated reason supplied for a bare causal/comparative/evaluative claim, or a fabricated mechanism removed from a claim that wrongly attributed it to the source. Apply inline. A non-obvious claim that no held source supports is not determinate and is never dropped on a single pass — route it through the bullet-removal guard below. Correct a distortion inline only when the faithful replacement is bounded: a single-bullet reword on one page the fact-check settles outright. A distortion whose faithful correction requires re-deriving an aggregate the pass cannot fully validate, spans more than one page, or produces wording audit cannot certify faithful this run routes to the distortion-disposition rule below, not to a forced inline rewrite.

**Repeated-literal sweep after any citation fix.** Search the distinctive literal across `1-wiki/` and re-check every occurrence. Fix each confirmed sibling and bring it into current scope; if it cannot be certified, set it `needs-update`, strip its hash, and carry no marker. A mis-located citation is a support failure, never neutral. Record the literal and sites checked.

**Authored fixes** — splitting an over-long or multi-idea page, merging near-duplicates, rewriting a source-shaped page, dropping a bullet the raw does not support (only through the bullet-removal guard), authoring a missing contradiction bullet, adding a missing cross-paradigm `Connections`/`Not This` link the relationship sweep surfaces (reciprocal on both pages): carry them out grounded in the fact-check, following ingest's existing-source-mode procedure for source-page content and the `supersede` procedure's preservation and bookkeeping mechanics.

- Each split-off or rewritten page is a new page: author it with the complete frontmatter template for its page type (`CLAUDE.md` → the page-type frontmatter block — a concept/entity page carries `type`, `aliases`, `sources`, `source_count`, `tags`, `created`/`updated`, `status: draft`; a synthesis additionally carries `origin` and, when applicable, `single_source_stub`) and all required callouts with block IDs, and let it earn `verified` only from its own fact-check, never by inheriting a parent's stamp.
- Copy the prior version to `2-outputs/supersede/preserve/`, naming the preserved copy per `.claude/skills/multi-skill/references/quarantine-path-convention.md` (a `-N` clash suffix before the final extension, then `git check-ignore -q` to confirm the copy did not land on a gitignored name — audit routinely does a split and a merge in one run, so a same-minute clash can otherwise silently lose the only preserved copy). Preserve the prior view there; update index/hot/log.
- When a fix removes or renames a page (a merge, a redirect, or a split that retires a slug), find and rewrite the body-prose inbound wikilinks that point at it, following `.claude/skills/multi-skill/references/inbound-reference-discovery.md` — `check_wiki.py` does not see prose wikilinks, so an inbound link left unrewritten dangles silently until a later lint.
- Inherit those mechanics but not supersede's approval gates: audit is the autonomy exception and asks the user nothing.

**Bullet removal requires the locator/entailment pair plus one independent destructive-correction reader.** The pair's two non-HOLDs make a removal candidate, not a deletion. The third reader reopens the legible raw with a different access strategy; the coordinator mechanically rechecks every returned quote and adjudicates evidence rather than vote count. Unreadability is `cannot_confirm`, never evidence of absence. Drop only when all three independently establish non-support; if any finds support, apply the correction it enables, and if evidence remains split or unreadable, preserve the bullet, mark it `*[tentative]*`, and set `needs-update` with the unresolved support question.

**A confirmed distortion audit cannot safely correct in-pass — the distortion-disposition rule — is set `needs-update`, not force-fixed and not deferred to the user.** A distortion whose faithful correction is not bounded to a single-bullet reword — it requires re-deriving an aggregate the pass cannot fully validate (recomputing a whole table or evidence base — `references/verification-spec.md`, the summary-claim discipline), the same distorted framing is inherited across more than one page (a source page and the concept/synthesis pages that lifted its wording), or audit cannot produce replacement wording it can certify faithful this run — is not force-fixed: a wrong rewrite re-certifies a fresh distortion, the asymmetric error the confirm-before-fixing guard prevents. Nor is it left as a passive finding for the user. Set every page the distortion touches `needs-update`, with a `needs_update_reason:` carrying the full derivation — the recomputed aggregate, the specific cells, and what the faithful claim must instead say — so the re-ingest or the user receives a precise hand-off, not a re-check. Find inherited siblings the way the repeated-literal sweep finds inherited citations — grep the distinctive phrase of the distorted framing across `1-wiki/` — and set each `needs-update` too. This is the general rule behind every status disposition: a confirmed defect always ends the run acted on — fixed when the correction is a safe in-pass determinate edit, set `needs-update` with a derivation when it is not.

**When a structural call is genuinely ambiguous** — is this one idea stated twice or two distinct ideas? does the merge target page survive or the merged-away one? — and the fact-check does not settle it, do not perform the surgery. Preserve the body, set the page `needs-update` with a `needs_update_reason:` naming the exact unresolved choice, and record the Warning identity as pending. Do not ask the user. If the Warning survives final lint, the audit is `incomplete`. Act autonomously only when the fact-check makes the structural call determinate; preserving the prior version is necessary but not sufficient licence to act on a coin-flip.

**Carry the markup on anything you author or move.** Each authored or moved callout carries its block ID as the last line inside the `>` block (`> ^idea`, `> ^evidence`, …; `CLAUDE.md` → Callout Block IDs). Each page locator you write or move carries its `#page=N` raw-file deep-link, in the form `CLAUDE.md` → Source Support And Verification defines for the page type:

- **Source page — one form** (`CLAUDE.md` → Source page rules): every source-page locator — `Evidence`/`Method` pointers and in-body non-obvious claim citations alike — carries the structural anchor and page together inside the `#page=N` deep-link display (`[[0-raw/papers/<stem>.pdf#page=N|sec. 4, p. M]]`, `[[0-raw/papers/<stem>.pdf#page=N|fig. 1, p. M]]`), used as a sentence subject, a leading `Evidence` label, or a trailing parenthetical. The source key is dropped (it would be a self-link). Do not split the anchor outside the link (`sec. 1, [[…#page=N|p. N]]`) or flatten to a page-only `|p. N` display — both drop the section the schema requires (lint `source_locator_incomplete`).
- **Concept/entity/synthesis page — the two canonical forms** (Form 1 attributive / Form 2 parenthetical, defined in `references/semantic-checks.md` and `CLAUDE.md` → Source Support And Verification): the source-page wikilink names which source, the parenthesized raw deep-link carries the anchor + page in its display. Form 2 wraps the whole citation in round brackets — `… claim ([[…|key]]; [[…|sec. X, p. M]])`.
- **The unpaginated-supplement exemption — on every page type** (`CLAUDE.md` → Source Support And Verification). Where the cited region genuinely has no printed page, cite its structural anchor alone, keyed on the pagination map: `[[0-raw/papers/<stem>.pdf#page=16|app. D.1, tab. 8]]`. Never fabricate a printed page. Confirm the absence in the raw. This locator change enters current scope; if its new anchor cannot certify under the HEAD gate, end `needs-update`, hashless and marker-free.
- Keep every locator inside a `[[…]]` display or a backticked span (a non-PDF uses a backticked per-type locator in place of the `#page=N` deep-link), with N the physical PDF page — a bare locator left as plain text after the link trips lint's `page_locator_unlinked`.

**Touch `updated:`** on every page whose body audit edits — inline and authored fixes alike. (The only exception is the full-mode no-correction case in SKILL.md → Verification Model, where a verified page is left unchanged and keeps its `updated:` and `verified_hash:`.)

**Strip a stale `verified_hash:`** on any page audit demotes to `draft` or `needs-update` — a non-`verified` page carries no `verified_hash:`; it is re-added only when audit next sets the page `verified` (Step 8).

Step 7 ends with every residual item terminal and every content-changing target queued for delta- or complete-page certification, or already safely `needs-update` without hash or process marker. Nothing in this lane is stamped. Step 4a neutral-only verified hosts remain verified; other neutral hosts remain in scope. A graph edit requires the Step 4b loop and cold restart before Step 8, which verifies the final bodies and sets status.
