# audit — verification spec (Step 5)

The detailed fact-check spec for `audit` Step 5: the coverage gate, the per-page-type callout checklist, the claim-by-claim axes, and the yes/no audit-assumption framing.

**Run it only where Step 5 has cause**, or on every claim in a `full`-mode pass. A certified, hash-matched claim is not re-checked here: the run that wrote it opened the raw and asked these same questions, and `verified_hash:` guarantees the text has not moved since. The five causes (SKILL.md → Verification Model gives the compact list):

- **An `*[unverified]*` claim**, wherever it sits — a claim no run has certified, standing cause on any page including a `verified` one.
- **A page carrying claims no run certified** — every `draft` and `needs-update`, plus any `verified` page whose `verified_hash:` is missing or no longer matches its body (a hand edit, a legacy page, a stamp predating the current model). The unstamped-`verified` guard in Step 5 is what catches the last kind.
- **A claim Step 4's page-level read gives a specific reason to doubt** — a summary or aggregate claim over a table, a framing inherited across several pages, wording that reads stronger than its cited section could support, a locator that looks transplanted. Specific means the doubt names what would refute it; a general unease is not cause, and acting on one is the false-positive fix `references/apply-fixes.md` forbids.
- **Any claim audit itself rewrites, splits out, merges in, or drops** — audit's own authoring is uncertified content, and a same-agent re-read of one's own rewrite is the most circular read there is.
- **A locator lint flagged** — `verified_anchor_unaudited` (an anchor added or changed on a `verified` page, whose certification the script cannot see: closed by the writing run's own record of certifying it, else settled here), `locator_page_mismatch`, `page_locator_unlinked`. Settle each by opening the raw at the cited page and reading the nearest heading above the cited text — never by inference from the page number or the wiki page.

Everything below is written for the claims that *do* reach this spec — where it applies, it applies in full, with no sampling shortcut.

**Coverage gate.** A `verified` stamp requires confirmed full-text coverage of the raw source, never the wiki source page as a proxy. Confirm coverage with a positive probe, not merely the absence of a symptom: the raw's final page or section is present and intelligible, and body text (not only figure captions) is extractable. For a book source page (`type: book`, scoped to a chapter or page range), coverage is judged against *that range* — the pages its claims cite present and intelligible, and the last page of the range readable — not the whole book: a book is ingested by an up-front page range (named in `title:`), so the other chapters being unread is the page's intended scope, not a coverage failure. If the raw cannot be fully read — file missing or moved, image-only scan, OCR-garbled, truncated extraction, encrypted or password-protected, or paywalled to an abstract (or, for a book, the scoped range cannot be read) — the page must not be promoted to `verified`. Set it `needs-update` with a `needs_update_reason:` naming the coverage failure (e.g. "raw is image-only scan; cannot fact-check"), and surface it as a Critical finding. This mirrors ingest's full-text-coverage gate, and binds here for the same reason: audit stamps the pages it promotes and re-stamps the ones it corrects. Before stamping `verified`, also spot-check the `#page=N` deep-links by opening the raw and confirming both that the cited content is there and that N resolves to the printed page the locator claims: read the printed number on the raw's first physical page to derive the offset (`first_printed − 1`), then confirm a cited link's physical page N actually carries printed page M — checking content presence alone passes a self-consistent wrong offset. The single-offset formula assumes one arabic run from the first physical page; on a source with roman-numeral front matter, unnumbered dividers, or several pagination runs (common in books and chapter-split sources audit covers), it breaks — there, locate the cited page's actual physical page directly rather than computing from one offset. For a registered raw, read what each page prints straight off the pagination map (`.claude/skills/multi-skill/pagination-map.md`) — the per-page record `lint`'s `locator_page_mismatch` checks every `p. M` against — rather than deriving `p. M` from a single offset a restarting appendix would defeat. Spot-check every `#page=N` whose offset was computed or changed this run, plus at least one already-present link per page, plus **every locator on a cross-source bullet — one naming two or more sources (`Contradictions`, `Tensions`, `Not This`, `Disconfirming Evidence`): open all of those at the cited page, no sampling.** As a deterministic pre-pass, run `python3 .claude/skills/multi-skill/scripts/cited_figure_check.py "1-wiki"` (with the `llm-wiki` conda env active for PyMuPDF; exit code 3 means PyMuPDF is absent — fall back to the manual sweep and note it) to seed and prioritize the worklist of numeric cross-source citations whose figure sits on none of the bullet's cited pages — lint's opt-in `cited_figure_off_page` backstop, which lint hands to audit to settle which half is wrong. Audit owns running it, as it owns `body_hash.py`; it augments, never replaces, the manual no-sampling sweep — it errs toward "present" and covers only decimals and percentages, so a clean script result never excuses a manual open of a cross-source locator, it only adds suspects. A single correct sample does not certify the rest — the abstract→sec.1 mis-offset class and the cross-source mis-location class (a true claim from source A cited to a locator in source B) are both per-locator, and a mis-located citation hides behind a good sibling when only one link per raw is opened. A page whose cross-source bullets were not locator-verified against their cited pages this run is not stamped on their strength: mark those bullets `*[unverified]*` (the hash excludes them) so the page can still be promoted on its verified content without certifying the unchecked cross-source citations, and the next partial audit re-checks and clears them. A guessed or mis-computed offset (e.g. assuming zero on a source not paginated from 1) is a silent-wrong link, not a verification pass (the same spot-check ingest's claim check requires). Figure or table *presence* is not evidence *sufficiency*: a claim that draws its value from an image-only or otherwise unreadable figure cannot be certified from the extractable caption alone, even when the page's body text is fully readable and the figure is present at its `#page=N` — do not stamp the claim `verified` off the caption. **But "no text layer" is not the same as "unreadable", and the attachment folder is checked before that verdict is reached.** The wiki extracts figures to `1-wiki/attachments/{stem}/` at ingest precisely so they can be read later, and the crop is usually there and usually legible with the values printed right on it — bar labels, wheel percentages, a summed decomposition. Open the source's attachment folder and read the crop before declaring the region unreadable; only when no crop exists, or the crop does not carry the cited value, does the region count as unreadable (mark the claim `*[tentative]*` and set the page `needs-update`). Skipping that check pulls back true, supported claims on a technicality of extraction tooling — a real loss, and a quiet one, since the page simply ends up saying less with nothing marked to show why. When audit clears an `*[unverified]*` marker, the raw locator that settled it is that page's spot-check; record the confirmed `#page=N` in the report, mirroring ingest's proof-of-read.

**Certify each claim that reaches this spec through the tiered independent-refuter gate.** Audit's fact-check is not a same-agent read: each non-obvious claim in scope is certified by independent refuter subagents at the tier its impact sets, per the shared spec (`.claude/skills/multi-skill/references/verification.md` → Tiered Independent-Refuter Verification; `CLAUDE.md` → Page status). Refuters are always required where audit will **certify or overwrite** content — a claim it is stamping, rewriting, correcting, or dropping — because that is where a wrong read becomes durable and self-concealing; where audit is only deciding whether to *raise* a doubt, its own read against the raw may settle it. The broad default is Tier 3 — three refuters, each spawned read-only (Read/Glob/Grep, no Edit/Write) from this top-level audit agent and given the claim and the raw, not the page's framing, each prompted to refute; a summary or generalization claim has each refuter recompute the whole set cold (the summary-claim discipline above), not the cited cell. The claim earns `verified` only on unanimous hold; any refutation, or a "cannot confirm" from a raw region unreadable by every available route (the attachment crop included — see the coverage gate above), is a split — mark the claim `*[unverified]*` / `*[tentative]*` and set the page `needs-update` (the distortion-disposition path), never certify on a split. Obvious / definitional bullets and the author's own marked judgement are Tier 0 (no refuter). Two prompting rules from that same shared section bind here unchanged: **name the defect shape** each refuter should hunt, varied across the tier; and read **a split as an explicit disagreement, not a gap in what the quorum happened to read** — a refuter's silence on a claim means it went unread, so have it read rather than recording a dispute, and close an unclosable split at `needs-update` with a `needs_update_reason:`, never `draft`. These refuters are audit's fan-out: the central post-fan-out pass (SKILL.md Step 8 / `references/verify-and-set-status.md` — locator-format normalization, the data-list quorum and all shared-file writes applied from the top-level agent, never nested) applies unchanged.

**Batch the claims, and batch the refuters.** Group claims into batches of roughly 25 and give the whole batch to **each refuter in the claim's tier** — three at the Tier-3 default — rather than spawning one subagent per claim or per page, so the quorum still holds per claim in three calls rather than 3×N. Per-claim fan-out multiplies spawn cost without buying independence, since independence comes from the reader being separate, not from the unit being small. Two constraints keep the economy from becoming a weaker gate. **Never split a batch across the tier's refuters** — that silently drops every claim in it to a single judgement (the same rule `references/apply-fixes.md` states for the batched ignore-list quorum). And **each refuter returns an explicit per-claim verdict — holds / refuted / cannot confirm — for every claim in its batch, never a selective list**: a claim a return omits is unread, not held, so re-issue it rather than counting the batch complete. Keep each batch within one raw where possible, so a refuter opens a source once and settles everything tracing to it in that pass.

Check every callout section against the raw — each faithful to the raw, metadata matching, no load-bearing part dropped or distorted:
- Source pages: TL;DR, Contribution, Key Claims, Evidence, Method, Assumptions, Limitations, Appraisal, Concepts and Entities, Contradictions, Open Questions, Connections.
- Concept/entity pages: Idea, Why It Matters, Not This, Examples, Contradictions, Disconfirming Evidence, Open Questions, Connections, Sources — and the page is one idea, written simply.
- Syntheses: every section, with each part of the answer mapped to the raw sources behind the listed source pages.

**Check claim by claim, not only section by section.** Within each callout, walk every non-obvious claim and verify it on both axes against the raw source: (a) support — it is obvious/definitional, the author's own marked judgement, or inline-cited to a source that genuinely backs it in one of the two canonical citation forms (CLAUDE.md → Source support and verification), with the located deep-link's anchor and page checked against the raw, not just present: the structural anchor names the actual section/figure the claim draws from and the physical page N resolves there (compute N from the printed→physical offset, never assume zero on a source not paginated from 1); and (b) faithfulness — its meaning, scope, and strength match what that source says, with no overstatement, narrowing, over-generalization, or misinterpretation (a correct restated number does not make a distorted claim faithful) — and, on a multi-source page especially, no cite-versus-contribute error (a result the source quotes from prior work presented as that source's own contribution) and no cross-source merge (a number, method, or result from a different source imported and attributed to this one), and when the source page carries `frames:` (one or more lenses scoping its summary) faithfulness is judged within the union of those frames — content the page omits because it falls outside every listed frame is in-scope-absent, not a faithfulness gap; and (c) reasoned — a causal, comparative, or evaluative claim states its reason or mechanism, not a bare conclusion (the source's reason, faithful to it, for a source claim; the user's own for own-voice judgement), and a mechanism the source does not give is never fabricated and attributed to it (that is a faithfulness violation, not a clarity nit). Obvious bullets and the author's own marked judgement (`Appraisal`, `Open Questions`, `Assumptions`) need no citation — do not manufacture citation wallpaper; but a sourced `Disconfirming Evidence` or synthesis `Tensions` bullet carries an inline citation like any non-obvious claim, exempt only when it is a purely own observation with no source. The fix in Step 7 is determinate where the fact-check settles it: add the missing inline citation once the raw identifies the supporting source, or correct wording that distorts the source; a non-obvious claim no held source supports is dropped or marked `*[tentative]*` with `needs-update`.

**Verify a summary or generalization claim by recomputing its full basis — never by confirming the cell it cites.** A claim that summarizes, aggregates, or generalizes over a set of values — "X fares worse", "most/all tasks improve", "the Y half degrades", "drops across the board", a mean or median, "on average", "consistently", "in every case" — is not verified by opening the one locator it cites and confirming that cell. The cited cell is the evidence the claim's author selected because it fits, so confirming it is the circular reading that certifies the distortion — this is exactly how the class survives a full audit: the check confirms the cells the bullet cites instead of recomputing the set they generalize over. Reconstruct the whole set the claim ranges over from the raw — every row, column, task, or condition it summarizes — compute the aggregate yourself, and test the claim against that. A claim true of the cited cell but false of the recomputed aggregate — three of six tasks improve while the summary says the half "fares worse"; the qualitative column degrades ~10× more than the numeric one the claim blames — is a faithfulness distortion however well-formed and correctly-numbered the cited cell is. Carry the recomputed aggregate into the finding's yes/no audit assumption and into the distortion-disposition rule (`references/apply-fixes.md`). This defect concentrates in the cross-source and comparison callouts (`Contradictions`, `Tensions`, `Not This`, `Disconfirming Evidence`), where a one-number generalization about which approach or column fares worse is the characteristic failure.

**Verify a source's stated position against the whole passage — a reason-clause reattached to the wrong subject inverts the source and passes every check.** When a bullet attributes a *position* to the source — a denial ("falls outside the scope of X"), a superlative ("the widest gap it reports"), a "by design", a "considers X to be Y" — read the full paragraph and confirm the source predicates that position of *this* subject, not of a neighbour in the same list, table, or appendix. Adjacent items usually carry different reasons — that is why they are separate sentences — so a reason-clause lifted from item A and reattached to item B inverts what the source says while the locator, the section, and the quoted fragments all stay correct. It survives a page-and-content spot-check and a lexical check; only reading the whole passage catches it. Distinct from cross-source mis-location (the wrong *source*): this is the wrong *subject* under a correct single source, and it concentrates in the same cross-source and comparison callouts.

**Verify a citation at the page it cites, not the document — and not by whether the claim is true.** For a cited claim the question is not "is this claim true?" but "is this claim on the page it cites?" A true claim with a wrong locator is a defect, and a more dangerous one than a false claim: its truth is what makes every reviewer nod it through. So open the raw at the cited physical page N and confirm the claim's content sits *there*. Scope the check to that page; never satisfy it with a document-wide search. A distinctive figure or name often recurs elsewhere in the same document — a different table, an unrelated metric, the bibliography — so grepping the whole raw for the literal returns a hit and "confirms" a bad citation; that false-confirmation path is the exact way a careful-looking verification certifies the error. Presence somewhere in the document is not presence at the cited page. On a cross-source bullet, verify each clause against the source it is cited to — the claim's origin, not the bullet's frame (CLAUDE.md → Source support and verification, the multi-source-bullet rule). Settle the *section anchor* by the nearest heading **above** the cited text, never by assuming the section from the page or inheriting it from the wiki page: `pdftotext -f N -l N raw.pdf - | grep -nE "^[0-9]+\.[0-9]*|^Abstract|^[A-Z]\.[0-9]"` lists the page's headings with line numbers, and the text belongs to the nearest heading whose line precedes it — two headings can share one physical page, so a heading being present on N does not put the text under it (the abstract→`sec. 1` mis-label and a section's tail sentence swept into the next section's number are both this error). PDF text is line-wrapped, so `tr '\n' ' '` before grepping any multi-word phrase in the extracted text, or the grep misses a match split across a line break and falsely reports "not found".

**Frame every Critical finding as a yes/no audit assumption** (design decision D 7.13 in `a-archive/reference/llm-wiki-design-decisions.md`). Format: `I assumed {X} because I saw {Y}. Correct?` followed by the proposed fix. This forces the audit pass to expose its load-bearing inference rather than rationalize drift. Example: instead of "page X overstates the gain", write "I assumed page X overstates the gain because the source's `Evidence` says 12-18% but the page's `Idea` bullet says 'large gain'. Correct?" then propose the fix. Apply the same yes/no framing to any Warning finding that will trigger an autonomous structural change in Step 7 (a split, a merge, a source-shaped rewrite, a dropped bullet) — those are exactly the load-bearing inferences most prone to rationalized drift, since audit both diagnoses and acts on them. Info findings, and Warnings that only flag without acting, stay in their plainer narrative form. The assumption framing keeps the load-bearing inference auditable in the report even though audit applies the fix autonomously (Step 7).

## The CLAUDE.md-change re-check gate

Run this gate in Step 6, after recording the run Mode, and record its verdict under **Recommendations**. Judge whether a CLAUDE.md or style change warrants re-checking already-verified pages — a re-check is warranted for **one narrow case only**. Cheap gate first: run `git log -1 --format=%ad -- CLAUDE.md a-archive/style` (plus `git status --porcelain` over the same paths for uncommitted edits) against the most recent `full` audit in `2-outputs/audit/` history; if neither changed since, no note is due. If either did, read the diff. The **only** change a `partial` run cannot already reach on a verified page is a change to the *criterion by which an already-present, well-formed claim is judged faithful to or adequately supported by its raw source* — e.g. tightening the summary/aggregate rule so a claim that confirmed its one cited cell must now recompute the whole table. The claim still looks compliant to lint and to Step 4's semantic pass, so only re-opening the raw under the new criterion reveals the staleness. For that case only, note under **Recommendations** that the affected verified pages need re-checking against their raw: prefer a targeted re-check — demote just those pages so the next `partial` re-verifies them — and recommend a whole-wiki `full` only when the affected class cannot be bounded. **Every other CLAUDE.md edit warrants no re-check,** because a cheaper mechanism already covers it: a format or locator-form change is a relocation (verification-neutral re-stamp); a required-callout or page-template change is structural (`lint`); a citation-presence, prose-style, atomicity, link, or redundancy rule is re-applied to every page — verified included — by Step 4 on the next `partial`, and Step 7 fixes it against the raw; and a process or cosmetic edit (a skill procedure, the report shapes, the log/hot format, the directory tree, the memory tiers, a typo, a reword) alters no page at all. Note such a change in passing without recommending a re-check.
